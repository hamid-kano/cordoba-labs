فكّرت في رقم من 1 إلى 1000، وطلبت من صديقك أن يخمّنه، وأنت تقول له فقط «أكبر» أو «أصغر». إذا بدأ من 1 ثم 2 ثم 3، قد يحتاج ألف محاولة. أما إذا بدأ بـ 500، فمهما كان جوابك، **تخلّص من نصف الأرقام** بسؤال واحد. وبهذه الحيلة يجد رقمك بـ **10 محاولات أو أقل، دائماً**. هذه الحيلة اسمها **البحث الثنائي**.

## ماذا ستتعلم؟

- **البحث الخطي**: أبسط طريقة، ومتى تكون الوحيدة الممكنة.
- **البحث الثنائي**: لماذا هو سريع جداً، وما شرطه.
- الأخطاء المشهورة في كتابة البحث الثنائي، وكيف تتجنّبها.
- البحث عن **أول موقع** لعنصر مكرر، ودوال البحث الجاهزة في اللغات.
- طرق أخرى: البحث بالقفز، والبحث بالاستيفاء.
- متى يستحق أن **نرتّب** القائمة قبل البحث.

## العب أولاً

**ماذا يجب أن ترى؟**

1. في «أنا أخمّن»: إذا اخترت المنتصف كل مرة (500، ثم 250 أو 750...)، ينكمش الشريط الأخضر إلى النصف مع كل تخمين، وتجد الرقم بـ 10 محاولات أو أقل.
2. في «الحاسوب يخمّن رقمي»: فكّر في أي رقم، حتى 1 أو 1000. لن يحتاج الحاسوب أكثر من 10 تخمينات.
3. جرّب أن تكذب مرة: سيكتشف الحاسوب أن إجاباتك متناقضة.

## البحث الخطي

نمرّ على العناصر **واحداً واحداً** من البداية، حتى نجد ما نريد أو تنتهي القائمة. ويُسمّى <Term t="البحث الخطي" en="Linear Search" def="البحث عن عنصر بفحص عناصر القائمة واحداً واحداً من البداية حتى نجده أو تنتهي القائمة." /> (أو التسلسلي).

```text
LINEAR-SEARCH(A, target):
    for i ← 0 to length(A) − 1:
        if A[i] = target:
            return i
    return −1          // not found
```

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def linear_search(a, target):
    for i, x in enumerate(a):
        if x == target:
            return i
    return -1

print(linear_search([7, 3, 9, 1], 9))  # 2
```

</TabItem>
<TabItem label="C++">

```cpp
int linearSearch(const vector<int>& a, int target) {
    for (int i = 0; i < (int)a.size(); i++)
        if (a[i] == target) return i;
    return -1;
}
// linearSearch({7, 3, 9, 1}, 9) == 2
```

</TabItem>
</Tabs>

| الحالة | عدد المقارنات |
| --- | --- |
| أفضل حالة: العنصر أولاً | 1، أي $O(1)$ |
| أسوأ حالة: العنصر آخراً أو غير موجود | n، أي $O(n)$ |
| الحالة المتوسطة | قرابة $n/2$، أي $O(n)$ |

**ميزته الكبرى:** يعمل على **أي** قائمة، مرتبة أو غير مرتبة. وإذا كانت القائمة غير مرتبة، فهو **الطريقة الوحيدة**: لا يمكن أن نعرف أن العنصر غير موجود دون أن ننظر إلى كل العناصر.

## البحث الثنائي

<Concept term="البحث الثنائي" en="Binary Search">

بحث في قائمة **مرتبة**: ننظر إلى العنصر في المنتصف. إذا كان هو المطلوب، انتهينا. وإذا كان المطلوب أصغر منه، نرمي النصف الأيمن كله، وإلا نرمي الأيسر. ونكرر مع النصف الباقي. مثل البحث عن كلمة في القاموس: لا تقرأه من الصفحة الأولى.

**لماذا نستخدمه؟** لأن كل مقارنة ترمي **نصف** الاحتمالات. مع مليون عنصر تكفي 20 مقارنة، ومع مليار عنصر 30 مقارنة فقط، أي $O(\log n)$.

**أين يُستخدم؟** في قواعد البيانات للبحث في الفهارس، وفي القواميس وجهات الاتصال، وفي أداة `git bisect` التي تجد اللقطة التي سبّبت خطأً بين مئات اللقطات، وفي حل مسائل كثيرة من نوع «ما أصغر قيمة تحقق الشرط؟».

</Concept>

```text
BINARY-SEARCH(A, target):          // A must be sorted
    lo ← 0
    hi ← length(A) − 1
    while lo ≤ hi:
        mid ← lo + (hi − lo) / 2
        if A[mid] = target:  return mid
        if A[mid] < target:  lo ← mid + 1    // drop the left half
        else:                hi ← mid − 1    // drop the right half
    return −1
```

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

print(binary_search([3, 6, 9, 12, 15, 18], 15))  # 4
```

</TabItem>
<TabItem label="C++">

```cpp
int binarySearch(const vector<int>& a, int target) {
    int lo = 0, hi = (int)a.size() - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;   // avoids overflow
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
// binarySearch({3, 6, 9, 12, 15, 18}, 15) == 4
```

</TabItem>

### السباق

<SearchRace />

**ماذا يجب أن ترى؟**

1. ابحث عن **72**: الخطي يقلب 24 بطاقة، والثنائي **2** فقط (48 ثم 72).
2. ابحث عن **48**: الثنائي يجده من أول نظرة، لأنه في المنتصف تماماً.
3. ابحث عن **3**: هذه أفضل حالة للخطي (بطاقة واحدة)، والثنائي يحتاج 5. الخطي قد يفوز أحياناً!
4. ابحث عن **50** (غير موجود): الخطي يقلب كل البطاقات الـ 32، والثنائي يكتشف أنه غير موجود بـ 5 فقط.

### لماذا log n؟

بعد كل مقارنة يبقى النصف: $n$ ثم $\frac{n}{2}$ ثم $\frac{n}{4}$... حتى يبقى عنصر واحد. وعدد مرات القسمة على 2 حتى نصل إلى 1 هو بالضبط $\log_2 n$. لذلك أسوأ حالة هي $\lfloor \log_2 n \rfloor + 1$ مقارنة:

| عدد العناصر | الخطي (أسوأ حالة) | الثنائي (أسوأ حالة) |
| --- | --- | --- |
| ‏1,000 | ‏1,000 | ‏10 |
| ‏1,000,000 | ‏1,000,000 | ‏20 |
| ‏1,000,000,000 | ‏1,000,000,000 | ‏30 |
| كل سكان الأرض (8 مليارات) | ‏8,000,000,000 | ‏33 |

### الشرط الذهبي

البحث الثنائي **يعمل فقط على قائمة مرتبة**. في قائمة غير مرتبة، عندما نرى أن العنصر في المنتصف أكبر من المطلوب، لا نعرف أي نصف نرمي، فقد يكون المطلوب في أي مكان.

## الأخطاء المشهورة

البحث الثنائي فكرة بسيطة جداً، لكن كتابته صحيحاً صعبة بشكل مفاجئ. يقول <Term t="Jon Bentley" en="Jon Bentley" def="عالم حاسوب أمريكي، مؤلف كتاب Programming Pearls، وجد أن أغلب المبرمجين المحترفين يكتبون البحث الثنائي بأخطاء." /> إنه طلب من مبرمجين محترفين كتابته، فكان في كود أغلبهم خطأ. وهذه أشهر الأخطاء:

| الخطأ | ماذا يحدث | الصحيح |
| --- | --- | --- |
| `while lo < hi` بدل `<=` | لا يفحص الحالة التي يبقى فيها عنصر واحد، فلا يجده | `while lo <= hi` |
| `lo = mid` بدل `mid + 1` | حلقة لا تنتهي عندما يبقى عنصران | `lo = mid + 1` و `hi = mid - 1` |
| `mid = (lo + hi) / 2` في C++ و Java | إذا كان lo و hi كبيرين جداً، يتجاوز مجموعهما أكبر عدد يمكن تخزينه، فيصبح سالباً | `mid = lo + (hi - lo) / 2` |
| البحث في قائمة غير مرتبة | نتيجة خاطئة دون أي رسالة خطأ | رتّب أولاً |

والخطأ الثالث اسمه <Term t="الفيضان العددي" en="Integer Overflow" def="أن تتجاوز نتيجة عملية حسابية أكبر عدد يستطيع المتغير أن يخزنه، فتنقلب إلى قيمة خاطئة، غالباً سالبة." />. وقد بقي هذا الخطأ مخفياً في مكتبة <Term t="Java" en="Java" def="لغة برمجة كائنية مشهورة، تُستخدم في تطبيقات أندرويد والأنظمة الكبيرة." /> الرسمية قرابة تسع سنوات، حتى اكتُشف عام 2006 مع القوائم الضخمة. أما في Python فالأعداد لا تفيض، فلا تظهر هذه المشكلة.

<Aside type="note" title="الثابت في الحلقة">
لكي تتأكد من صحة البحث الثنائي، تذكّر جملة واحدة تبقى صحيحة في كل دورة: **«إذا كان المطلوب موجوداً، فهو بين lo و hi»**. هذه الجملة اسمها <Term t="الثابت" en="Loop Invariant" def="جملة تبقى صحيحة قبل كل دورة من الحلقة وبعدها، ونستخدمها لنثبت أن الخوارزمية صحيحة." />. كل سطر يجب أن يحافظ عليها: عندما نكتب `lo = mid + 1` نكون متأكدين أن المطلوب ليس في `mid` ولا قبله.
</Aside>

## أول موقع، ودوال جاهزة

إذا تكرر العنصر، مثل `[2, 5, 5, 5, 8]`، فالبحث الثنائي العادي قد يعيد أي واحد من الخمسات. وأحياناً نريد **أول** موقع. الحيلة: عندما نجده، لا نتوقف، بل نحفظه ونكمل البحث في النصف الأيسر:

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
from bisect import bisect_left

a = [2, 5, 5, 5, 8]
print(bisect_left(a, 5))   # 1  first position of 5
print(bisect_left(a, 6))   # 4  where 6 would be inserted

def first_position(a, target):
    lo, hi, ans = 0, len(a) - 1, -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            ans = mid          # remember, keep looking left
            hi = mid - 1
        elif a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return ans
```

</TabItem>
<TabItem label="C++">

```cpp
#include <algorithm>

vector<int> a = {2, 5, 5, 5, 8};
auto it = lower_bound(a.begin(), a.end(), 5);
int first = it - a.begin();                          // 1
bool found = binary_search(a.begin(), a.end(), 6);   // false

int firstPosition(const vector<int>& a, int target) {
    int lo = 0, hi = (int)a.size() - 1, ans = -1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) { ans = mid; hi = mid - 1; }
        else if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return ans;
}
```

</TabItem>
</Tabs>

في المسابقات والعمل الحقيقي، **استخدم الدوال الجاهزة**: `bisect_left` في Python، و `lower_bound` و `binary_search` في C++. فهي مكتوبة ومُختبرة جيداً.

## طرق بحث أخرى

| الطريقة | الفكرة | التعقيد |
| --- | --- | --- |
| **البحث بالقفز** | نقفز $\sqrt{n}$ عنصراً كل مرة حتى نتجاوز المطلوب، ثم نرجع خطياً | $O(\sqrt{n})$ |
| **البحث بالاستيفاء** | نخمّن المكان حسب القيمة، كما تفتح القاموس قرب آخره لكلمة تبدأ بحرف «ي» | $O(\log \log n)$ إذا كانت القيم موزعة بانتظام، و $O(n)$ في أسوأ حالة |
| **البحث الأُسّي** | نجرّب المواقع 1، 2، 4، 8... حتى نتجاوز المطلوب، ثم بحث ثنائي | $O(\log n)$، ومفيد عندما لا نعرف طول القائمة |
| **جدول التجزئة** | نحسب مكان العنصر مباشرة من قيمته | $O(1)$ في المتوسط (سنراه في المستوى الثاني) |

## هل نرتّب أولاً؟

الترتيب له كلفة: أسرع الخوارزميات تحتاج $O(n \log n)$. فهل يستحق؟

- إذا كنا سنبحث **مرة واحدة**: لا. البحث الخطي $O(n)$ أسرع من الترتيب نفسه.
- إذا كنا سنبحث **k مرة**: الخطي يكلّف $k \times n$، والترتيب ثم البحث الثنائي يكلّف $n \log n + k \log n$. فإذا كان k كبيراً، **الترتيب يستحق**.

مثال: قائمة طلاب فيها مليون اسم، ونبحث فيها 1000 مرة يومياً. الخطي: مليار مقارنة. الترتيب مرة واحدة ثم الثنائي: قرابة 20 مليون + 20 ألف. أسرع بخمسين مرة تقريباً.

## الخلاصة

- **البحث الخطي** $O(n)$: يعمل على أي قائمة، وهو الوحيد الممكن إذا كانت غير مرتبة.
- **البحث الثنائي** $O(\log n)$: كل مقارنة ترمي نصف الاحتمالات. مليار عنصر بـ 30 مقارنة.
- شرطه الذهبي: **القائمة مرتبة**.
- أخطاؤه المشهورة: `<` بدل `<=`، و `mid` بدل `mid ± 1`، والفيضان في `(lo + hi) / 2`.
- استخدم الدوال الجاهزة: `bisect_left` في Python و `lower_bound` في C++.
- **الترتيب أولاً** يستحق إذا كنا سنبحث مرات كثيرة.

<details class="answer">
<summary>ما الثابت في حلقة البحث الثنائي، ولماذا هو مهم؟</summary>

</details>

<details class="answer">

</details>

<details class="answer">
<summary>كيف يستخدم المبرمجون البحث الثنائي لإيجاد لقطة Git التي سبّبت خطأً؟</summary>
