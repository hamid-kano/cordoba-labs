<Aside type="tip" title="الفكرة ببساطة">
مكتبتك في البيت: يمكن أن ترتّب الكتب على **رف** واحد بجانب بعضها، فتصل إلى الكتاب العاشر مباشرة، لكن إذا أردت كتاباً جديداً في أول الرف يجب أن تزيح كل الكتب. ويمكن أن تضع الكتب في **صناديق** متفرقة، وفي كل صندوق ورقة تقول «الكتاب التالي في الصندوق الأزرق». هنا الإضافة سهلة، لكن الوصول إلى الكتاب العاشر يحتاج أن تتبع الأوراق. لا توجد طريقة أفضل دائماً، بل **طريقة أنسب لكل عمل**. وهذا هو موضوع **بنى البيانات**.

## ماذا ستتعلم؟

- ما هي **بنية البيانات**، ولماذا اختيارها مهم بقدر اختيار الخوارزمية.
- **المصفوفة**: لماذا الوصول إليها فوري، ولماذا الإدراج في أولها مكلف.
- **المصفوفة الديناميكية**: كيف «تكبر» القائمة في Python و C++.
- **القائمة المرتبطة** بأنواعها، ومتى تفضّلها.
- **المكدس** و**الطابور**، وأين يعملان في حاسوبك الآن.
- كيف تفحص الأقواس بالمكدس، وما هو **الطابور الدائري**.

## ما هي بنية البيانات؟

<Concept term="بنية البيانات" en="Data Structure">

**طريقة لتنظيم البيانات في الذاكرة**، مع العمليات المسموحة عليها (إضافة، وحذف، وبحث، وقراءة). مثل الفرق بين دفتر هاتف مرتب أبجدياً، وأوراق متناثرة على الطاولة: المعلومات نفسها، لكن الوصول إليها مختلف تماماً.

**لماذا نستخدمها؟** لأن سرعة الخوارزمية تعتمد على البنية التي تعمل عليها. البحث الثنائي مثلاً يحتاج بنية تسمح بالقفز إلى المنتصف فوراً. والقاعدة المشهورة: **«خوارزمية + بنية بيانات = برنامج»**.

**أين تُستخدم؟** في كل برنامج: قائمة جهات الاتصال، وسجل المتصفح، وطابور الطباعة، وزر «تراجع» في محرر النصوص، وكل قاعدة بيانات.

</Concept>

## المصفوفة

<Term t="المصفوفة" en="Array" def="بنية تحفظ العناصر في خانات متجاورة في الذاكرة، لكل خانة رقم يبدأ من صفر، فنصل إلى أي خانة مباشرة بحساب عنوانها." /> خانات **متجاورة** في الذاكرة، لكل خانة رقم (يبدأ من 0). ولأنها متجاورة، يحسب الحاسوب عنوان أي خانة مباشرة:

$$
\text{address}(i) = \text{start} + i \times \text{size}
$$

فالوصول إلى الخانة رقم 5 أو رقم 5,000,000 يأخذ الوقت نفسه: $O(1)$. لكن الخانات المتجاورة لها ثمن: لكي تُدخل عنصراً في البداية، يجب أن **تزيح** كل العناصر خانة إلى اليمين.

## القائمة المرتبطة

<Term t="القائمة المرتبطة" en="Linked List" def="بنية من عُقد متفرقة في الذاكرة، كل عقدة فيها قيمة ومؤشر إلى العقدة التالية، مثل عربات قطار مربوطة ببعضها." /> مجموعة **عُقد** متفرقة في الذاكرة. كل عقدة فيها قيمة، و<Term t="مؤشر" en="Pointer" def="متغير يحفظ عنوان مكان آخر في الذاكرة، فيشير إليه، مثل ورقة مكتوب عليها رقم غرفة." /> إلى العقدة التالية. ونحفظ فقط مؤشراً إلى العقدة الأولى اسمه **الرأس**. مثل عربات قطار: كل عربة مربوطة بالتي بعدها، ولكي تصل إلى العربة العاشرة يجب أن تمشي في القطار.

### السباق

<ArrayVsList />

**ماذا يجب أن ترى؟**

1. **أدخل في البداية:** المصفوفة تزيح العناصر السبعة واحداً واحداً (برتقالي)، والقائمة تنشئ عقدة واحدة (أخضر) فوراً.
2. **اقرأ العنصر رقم 6:** المصفوفة تقفز إليه مباشرة، والقائمة تمشي 7 خطوات من الرأس.
3. **احذف الأول:** المصفوفة تزيح الجميع إلى اليسار، والقائمة تحرّك مؤشر الرأس فقط.
4. أضف حتى تمتلئ المصفوفة (10 خانات): ستقول إنها امتلأت! أما القائمة فلا حدّ لها إلا الذاكرة.

| العملية | المصفوفة | القائمة المرتبطة |
| --- | --- | --- |
| قراءة العنصر رقم k | $O(1)$ | $O(k)$ |
| إدراج أو حذف في البداية | $O(n)$ | $O(1)$ |
| إدراج في النهاية | $O(1)$ (إن وُجد مكان) | $O(1)$ مع مؤشر للذيل |
| إدراج في الوسط (بعد أن نصل إليه) | $O(n)$ | $O(1)$ |
| البحث عن قيمة | $O(n)$، أو $O(\log n)$ إن كانت مرتبة | $O(n)$ دائماً، فلا يمكن البحث الثنائي |
| ذاكرة إضافية | لا شيء | مؤشر لكل عنصر |

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next             # pointer to the next node

class LinkedList:
    def __init__(self):
        self.head = None

    def push_front(self, value):     # O(1)
        self.head = Node(value, self.head)

    def get(self, k):                # O(k): walk from the head
        cur = self.head
        for _ in range(k):
            cur = cur.next
        return cur.value

    def __iter__(self):
        cur = self.head
        while cur:
            yield cur.value
            cur = cur.next

lst = LinkedList()
for x in [3, 2, 1]:
    lst.push_front(x)
print(list(lst))   # [1, 2, 3]
```

</TabItem>
<TabItem label="C++">

```cpp
struct Node {
    int value;
    Node* next;                      // pointer to the next node
};

struct LinkedList {
    Node* head = nullptr;

    void pushFront(int v) {          // O(1)
        head = new Node{v, head};
    }
    int get(int k) {                 // O(k)
        Node* cur = head;
        while (k--) cur = cur->next;
        return cur->value;
    }
    ~LinkedList() {                  // free the memory
        while (head) { Node* t = head; head = head->next; delete t; }
    }
};
```

</TabItem>

### أنواع القوائم المرتبطة

| النوع | الفكرة | ميزته |
| --- | --- | --- |
| **أحادية** | كل عقدة تشير إلى التالية فقط | الأبسط والأقل ذاكرة |
| **مزدوجة** | كل عقدة تشير إلى التالية **والسابقة** | نمشي في الاتجاهين، ونحذف أي عقدة بـ $O(1)$ إذا كانت معنا |
| **دائرية** | آخر عقدة تشير إلى الأولى | مناسبة للأدوار المتكررة، مثل دور اللاعبين في لعبة |

وتُستخدم المزدوجة في سجل المتصفح (رجوع وتقدّم)، وفي قائمة الأغاني (السابقة والتالية).

## المصفوفة الديناميكية: أفضل ما في العالمين

القوائم في Python (`list`) و `vector` في C++ ليست قوائم مرتبطة، بل <Term t="مصفوفة ديناميكية" en="Dynamic Array" def="مصفوفة تكبر تلقائياً: إذا امتلأت تنشئ مصفوفة أكبر بمرتين تقريباً وتنسخ العناصر إليها، فتبقى الإضافة في النهاية سريعة في المتوسط." />: مصفوفة عادية، فإذا امتلأت تنشئ مصفوفة **ضعف** حجمها، وتنسخ العناصر إليها.

النسخ مكلف ($O(n)$)، لكنه **نادر**: بعد النسخ عند 8 عناصر، لن ننسخ مرة أخرى حتى 16، ثم 32... فإذا أضفنا n عنصراً، يكون مجموع النسخ $1 + 2 + 4 + \dots + n < 2n$. أي أن **كل إضافة تكلّف $O(1)$ في المتوسط**. وهذا النوع من التحليل اسمه <Term t="التحليل المُطفأ" en="Amortized Analysis" def="حساب متوسط كلفة العملية على سلسلة طويلة من العمليات، فالعملية النادرة المكلفة تتوزع كلفتها على العمليات الرخيصة الكثيرة." />.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
a = []
a.append(5)        # end: O(1) amortized
a.insert(0, 7)     # front: O(n), shifts everything
x = a[1]           # read: O(1)
a.pop()            # remove from end: O(1)
a.pop(0)           # remove from front: O(n)
```

</TabItem>
<TabItem label="C++">

```cpp
vector<int> a;
a.push_back(5);            // end: O(1) amortized
a.insert(a.begin(), 7);    // front: O(n)
int x = a[1];              // read: O(1)
a.pop_back();              // remove from end: O(1)
a.erase(a.begin());        // remove from front: O(n)
```

</TabItem>
</Tabs>

<Aside type="caution" title="خطأ شائع جداً">
`a.pop(0)` أو `a.insert(0, x)` داخل حلقة يجعل برنامجك $O(n^2)$ دون أن تنتبه! إذا احتجت الإضافة والحذف من الطرفين، استخدم `collections.deque` في Python، أو `std::deque` في C++.
</Aside>

## المكدس والطابور

هاتان البنيتان لا تسمحان بكل شيء، بل **تقيّدان** من أين ندخل ومن أين نخرج. وهذا القيد هو قوتهما.

<Concept term="المكدس" en="Stack">

بنية ندخل إليها ونخرج منها من **طرف واحد** فقط، اسمه القمة. فآخر عنصر يدخل هو أول عنصر يخرج: <Term t="LIFO" en="Last In, First Out" def="آخر من يدخل أول من يخرج: قاعدة المكدس، مثل كومة الصحون." />. مثل كومة الصحون: تضع الصحن فوق، وتأخذ من فوق.

**لماذا نستخدمه؟** عندما نحتاج أن **نرجع** بعكس الترتيب الذي تقدّمنا به: نرجع من الدوال المتداخلة، ونتراجع عن آخر تعديل، ونغلق آخر قوس فُتح.

**أين يُستخدم؟** في مكدس الاستدعاءات الذي رأيته في [العودية](../recursion/)، وزر «تراجع» في كل برنامج، وزر «رجوع» في المتصفح، وفي فحص الأقواس وحساب التعابير الرياضية في الحاسبة.

</Concept>

<Concept term="الطابور" en="Queue">

بنية ندخل إليها من **طرف** (الخلف)، ونخرج من **الطرف الآخر** (الأمام). فأول من يدخل أول من يخرج: <Term t="FIFO" en="First In, First Out" def="أول من يدخل أول من يخرج: قاعدة الطابور، مثل طابور المخبز." />. مثل طابور المخبز.

**لماذا نستخدمه؟** عندما نريد أن نخدم الطلبات **بعدل**، بترتيب وصولها، ولا ننسى أحداً.

**أين يُستخدم؟** طابور الطباعة، وطلبات الخادم، والرسائل بين البرامج، وفي خوارزمية البحث بالعرض في الرسوم البيانية (المستوى الثالث).

</Concept>

<StackQueueLab />

**ماذا يجب أن ترى؟** أضف A ثم B ثم C، ثم أخرج ثلاث مرات. المكدس يخرجها **C B A** (بالعكس)، والطابور يخرجها **A B C** (بالترتيب).

| العملية | المكدس | الطابور |
| --- | --- | --- |
| إضافة | `push` في القمة | `enqueue` في الخلف |
| إخراج | `pop` من القمة | `dequeue` من الأمام |
| النظر دون إخراج | `peek` / `top` | `front` |
| التعقيد | $O(1)$ للجميع | $O(1)$ للجميع |

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
from collections import deque

stack = []
stack.append("A"); stack.append("B")
print(stack.pop())       # B  (last in, first out)

queue = deque()
queue.append("A"); queue.append("B")
print(queue.popleft())   # A  (first in, first out), O(1)
```

</TabItem>
<TabItem label="C++">

```cpp
#include <stack>
#include <queue>

stack<string> st;
st.push("A"); st.push("B");
cout << st.top(); st.pop();      // B

queue<string> q;
q.push("A"); q.push("B");
cout << q.front(); q.pop();      // A
```

</TabItem>
</Tabs>

### تطبيق: فحص الأقواس

هل الأقواس في `{ a * (b + c) - [d / e] }` صحيحة؟ القاعدة: كل قوس يُغلق يجب أن يطابق **آخر** قوس فُتح ولم يُغلق. و«آخر ما فُتح» هو بالضبط ما يعطيه المكدس:

1. قوس فاتح ← ضعه في المكدس.
2. قوس مغلق ← يجب أن يطابق قمة المكدس، فنرفعها. وإلا فالنص خاطئ.
3. في النهاية يجب أن يكون المكدس **فارغاً**.

<BracketLab />

**ماذا يجب أن ترى؟** النص الأول صحيح. جرّب `([)]`: يتوقف عند `)` لأن آخر قوس مفتوح هو `[`. وجرّب `((()`: يصل إلى النهاية وفي المكدس قوس لم يُغلق. وجرّب `())(`: يتوقف عند `)` الثانية لأن المكدس فارغ.

هذه الطريقة نفسها يستخدمها **كل مترجم** لغة برمجة ليكتشف الأقواس الناقصة في كودك، وكل محرر نصوص ليلوّن القوس المقابل.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def balanced(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for c in s:
        if c in "([{":
            stack.append(c)
        elif c in pairs:
            if not stack or stack.pop() != pairs[c]:
                return False
    return not stack            # nothing left open

print(balanced("{[()()]}"), balanced("([)]"))   # True False
```

</TabItem>
<TabItem label="C++">

```cpp
bool balanced(const string& s) {
    map<char, char> pairs = {{')', '('}, {']', '['}, {'}', '{'}};
    stack<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') st.push(c);
        else if (pairs.count(c)) {
            if (st.empty() || st.top() != pairs[c]) return false;
            st.pop();
        }
    }
    return st.empty();
}
```

</TabItem>
</Tabs>

### الطابور الدائري

كيف نبني طابوراً بمصفوفة؟ إذا أخرجنا من الأمام بإزاحة الجميع، تصبح كل عملية $O(n)$. الحيلة: لا نزيح شيئاً، بل نحفظ رقمين: **أين الأمام** و**أين الخلف**، ونتحرك بهما. وعندما يصل أحدهما إلى آخر المصفوفة **يلتف** إلى أولها، كأن المصفوفة دائرة. وهذا اسمه <Term t="الطابور الدائري" en="Circular Buffer" def="طابور مبني على مصفوفة ثابتة الحجم، يلتف فيه مؤشرا الأمام والخلف إلى بداية المصفوفة عندما يصلان إلى نهايتها، فلا نحتاج إزاحة أي عنصر." />:

```text
next_index = (index + 1) mod capacity
```

ويُستخدم في الأجهزة التي تستقبل بيانات باستمرار: لوحة المفاتيح، وبطاقة الصوت، وتسجيل الفيديو، حيث نحفظ «آخر 10 ثوانٍ» مثلاً.

## الخلاصة

- **المصفوفة**: خانات متجاورة. القراءة برقم الخانة $O(1)$، والإدراج والحذف في البداية $O(n)$.
- **القائمة المرتبطة**: عُقد ومؤشرات. الإدراج والحذف في البداية $O(1)$، والقراءة بالرقم $O(n)$، ولا بحث ثنائي.
- **المصفوفة الديناميكية** (`list` و `vector`): تتضاعف عند الامتلاء، فالإضافة في النهاية $O(1)$ مُطفأ.
- **المكدس** LIFO: التراجع، ومكدس الاستدعاءات، والأقواس.
- **الطابور** FIFO: الخدمة بالترتيب، والبحث بالعرض. ويُبنى بمصفوفة بفكرة **الطابور الدائري**.

<details class="answer">
<summary>لماذا الإضافة في نهاية المصفوفة الديناميكية O(1) في المتوسط، مع أنها تنسخ كل العناصر أحياناً؟</summary>

لأن النسخ يحدث فقط عندما تمتلئ، والحجم يتضاعف كل مرة. فمع n إضافة، مجموع ما يُنسخ أقل من 2n، أي أقل من عنصرين لكل إضافة في المتوسط.
</details>

<details class="answer">
<summary>كيف تبني طابوراً باستخدام مكدسين فقط؟</summary>

ندخل دائماً في المكدس الأول. وعند الإخراج: إذا كان المكدس الثاني فارغاً، ننقل إليه كل عناصر الأول (فينعكس ترتيبها)، ثم نخرج من الثاني. كل عنصر يُنقل مرة واحدة فقط، فالكلفة O(1) مُطفأة.
</details>
