<Aside type="tip" title="الفكرة ببساطة">
شركة كهرباء تريد أن توصل سبع قرى بالشبكة. يمكنها أن تمد كابلاً بين أي قريتين متجاورتين، ولكل كابل كلفة. لا تحتاج أن تصل كل قرية بكل قرية: يكفي أن تصل الكهرباء إلى الجميع **بأي طريق**. ما أرخص مجموعة كابلات تفعل ذلك؟ هذه مسألة **الشجرة الممتدة الصغرى**، وحلها بسيط بشكل مدهش: **ابدأ دائماً بالأرخص، وتجنّب الحلقات**.
</Aside>

## ماذا ستتعلم؟

- ما هي **الشجرة الممتدة**، ولماذا فيها دائماً $V - 1$ ضلعاً.
- خوارزمية **Kruskal**: الأضلاع من الأرخص، مع رفض الحلقات.
- بنية **الاتحاد والبحث** التي تكشف الحلقة بسرعة.
- خوارزمية **Prim**: شجرة تكبر من عقدة واحدة.
- **خاصية القطع**: لماذا الطمع هنا صحيح.
- الفرق بين الشجرة الممتدة الصغرى وأقصر طريق.

## الشجرة الممتدة

<Concept term="الشجرة الممتدة الصغرى" en="Minimum Spanning Tree (MST)">

مجموعة من أضلاع الرسم **تصل كل العقد** (ممتدة)، **دون أي حلقة** (شجرة)، و**مجموع أوزانها أقل ما يمكن** (صغرى). مثل شبكة كابلات تصل كل القرى بأقل كلفة.

**لماذا نستخدمها؟** لأن كل مشروع «اربط الجميع» يريد أقل كلفة: كابلات، وأنابيب، وطرق، وشبكات حاسوب. وأي ضلع يصنع حلقة **زائد**، لأن العقدتين متصلتان أصلاً.

**أين تُستخدم؟** في تصميم شبكات الكهرباء والماء والاتصالات، وتوصيل الدارات الإلكترونية، وتجميع البيانات في الذكاء الصنعي (نقطع أطول الأضلاع فتنفصل المجموعات)، وتقريب حلول مسائل صعبة مثل البائع المتجول (الصفحة 19).

</Concept>

**حقيقة مهمة:** أي شجرة تصل V عقدة فيها **بالضبط V − 1 ضلعاً**. أقل من ذلك: تبقى عقدة منفصلة. وأكثر: تظهر حلقة حتماً. لذلك 7 قرى تحتاج 6 كابلات بالضبط.

## خوارزمية Kruskal

1. رتّب كل الأضلاع من الأرخص إلى الأغلى.
2. مرّ عليها بالترتيب: إذا كان الضلع يصل **مجموعتين منفصلتين**، خذه. وإذا كان طرفاه في المجموعة نفسها (سيصنع حلقة)، ارفضه.
3. توقّف عندما تأخذ $V - 1$ ضلعاً.

السؤال الصعب: كيف نعرف بسرعة هل عقدتان «في المجموعة نفسها»؟ الجواب بنية اسمها <Term t="الاتحاد والبحث" en="Union-Find" def="بنية تحفظ مجموعات منفصلة، ولها عمليتان: «ابحث» تعطي ممثّل مجموعة العنصر، و«اتحد» تدمج مجموعتين. مع تحسين ضغط الطريق، كل عملية تقريباً O(1)." />: لكل مجموعة «زعيم»، وكل عنصر يشير إلى من فوقه حتى نصل إلى الزعيم. عنصران في المجموعة نفسها إذا كان لهما الزعيم نفسه. ودمج مجموعتين: نجعل زعيم إحداهما يشير إلى زعيم الأخرى.

<TabItem label="Python">

```python
def kruskal(nodes, edges):              # edges: (w, a, b)
    parent = {v: v for v in nodes}

    def find(x):                         # walk up to the leader
        while parent[x] != x:
            parent[x] = parent[parent[x]]   # path compression
            x = parent[x]
        return x

    tree, total = [], 0
    for w, a, b in sorted(edges):        # cheapest first
        ra, rb = find(a), find(b)
        if ra != rb:                     # different groups: no cycle
            parent[ra] = rb              # union
            tree.append((a, b, w))
            total += w
            if len(tree) == len(nodes) - 1:
                break
    return tree, total

edges = [(7, "A", "B"), (5, "A", "D"), (8, "B", "C"), (9, "B", "D"),
         (7, "B", "E"), (5, "C", "E"), (15, "D", "E"), (6, "D", "G"),
         (8, "E", "G"), (9, "E", "F"), (11, "F", "G"), (12, "C", "F")]
print(kruskal("ABCDEFG", edges)[1])     # 39
```

```cpp
struct DSU {
    vector<int> p;
    DSU(int n) : p(n) { iota(p.begin(), p.end(), 0); }
    int find(int x) { return p[x] == x ? x : p[x] = find(p[x]); }   // path compression
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;        // same group: would make a cycle
        p[a] = b;
        return true;
    }
};

int kruskal(int n, vector<array<int,3>> edges) {   // {w, a, b}
    sort(edges.begin(), edges.end());
    DSU d(n);
    int total = 0, used = 0;
    for (auto [w, a, b] : edges)
        if (d.unite(a, b)) {
            total += w;
            if (++used == n - 1) break;
        }
    return total;
}
```

</TabItem>

**التعقيد:** الترتيب $O(E \log E)$، والباقي تقريباً $O(E)$ بفضل الاتحاد والبحث. فالمجموع $O(E \log E)$.

## خوارزمية Prim

طريقة أخرى تصل إلى النتيجة نفسها: نبدأ من قرية واحدة، و**نكبّر الشجرة** قرية بعد قرية. في كل خطوة نأخذ **أرخص كابل يخرج من الشجرة** إلى قرية جديدة.

من «الوادي» في مثالنا: الوادي–السهل (5)، ثم السهل–الطاحون (6)، ثم الوادي–التل (7)، ثم التل–الجسر (7)، ثم الجسر–النبع (5)، ثم الجسر–البيدر (9). المجموع **39** أيضاً.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
import heapq

def prim(graph, start):                  # graph[u] = [(w, v), ...]
    seen = {start}
    pq = list(graph[start])
    heapq.heapify(pq)
    total = 0
    while pq and len(seen) < len(graph):
        w, v = heapq.heappop(pq)         # cheapest edge leaving the tree
        if v in seen:
            continue
        seen.add(v)
        total += w
        for edge in graph[v]:
            if edge[1] not in seen:
                heapq.heappush(pq, edge)
    return total
```

</TabItem>
<TabItem label="C++">

```cpp
int prim(const vector<vector<pair<int,int>>>& g) {   // g[u] = {(w, v)}
    vector<bool> seen(g.size(), false);
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
    pq.push({0, 0});
    int total = 0;
    while (!pq.empty()) {
        auto [w, u] = pq.top(); pq.pop();
        if (seen[u]) continue;
        seen[u] = true;
        total += w;
        for (auto e : g[u]) if (!seen[e.second]) pq.push(e);
    }
    return total;
}
```

| | **Kruskal** | **Prim** |
| --- | --- | --- |
| الفكرة | الأضلاع من الأرخص، دون حلقات | شجرة تكبر من عقدة |
| البنية المساعدة | الاتحاد والبحث | طابور أولوية |
| الزمن | $O(E \log E)$ | $O(E \log V)$ |
| أنسب لـ | الرسوم المتفرقة، أو عندما تكون الأضلاع مرتبة أصلاً | الرسوم الكثيفة |

## لماذا الطمع صحيح هنا؟

أخذنا الأرخص دائماً، ولم نرجع عن أي قرار. لماذا لا يخدعنا ذلك؟ بسبب <Term t="خاصية القطع" en="Cut Property" def="إذا قسمنا العقد إلى مجموعتين بأي طريقة، فإن أرخص ضلع يعبر بين المجموعتين ينتمي إلى شجرة ممتدة صغرى." />:

> قسّم القرى إلى مجموعتين بأي طريقة. **أرخص** كابل يعبر بين المجموعتين موجود في أفضل حل.

لماذا؟ لو كان هناك حل لا يستخدمه، فلا بد أنه يستخدم كابلاً آخر أغلى يعبر بين المجموعتين (وإلا لما اتصلتا). استبدله بالأرخص: تبقى القرى متصلة، وتقل الكلفة. فالحل الأول لم يكن الأفضل! وكل كابل يأخذه Kruskal أو Prim هو أرخص كابل يعبر بين مجموعتين، فهو صحيح.

## الشجرة الصغرى ليست أقصر طريق

خطأ شائع: الشجرة الممتدة الصغرى تقلل **المجموع الكلي** للكابلات، لا المسافة بين قريتين بالذات. في مثالنا، الطريق من «الوادي» إلى «البيدر» في الشجرة: 7 + 7 + 9 = 23. لكن في الرسم الأصلي طريق أقصر: الوادي ← السهل ← الطاحون ← البيدر = 5 + 6 + 11 = 22. والشجرة لا تهتم بذلك. فإذا أردت **أسرع وصول** بين نقطتين، استخدم [Dijkstra](../shortest-path/). وإذا أردت **أرخص شبكة** تصل الجميع، استخدم الشجرة الممتدة.

## الخلاصة

- **الشجرة الممتدة الصغرى**: أضلاع تصل كل العقد، دون حلقات، بأقل مجموع. وفيها $V - 1$ ضلعاً.
- **Kruskal**: الأضلاع من الأرخص، ونرفض ما يصنع حلقة، بمساعدة **الاتحاد والبحث**.
- **Prim**: شجرة تكبر من عقدة، بأرخص ضلع يخرج منها، بمساعدة **طابور أولوية**.
- **خاصية القطع** تثبت أن الطمع صحيح هنا.
- الشجرة الصغرى ≠ أقصر طريق: الأولى تقلل **المجموع**، والثاني يقلل **المسافة بين نقطتين**.
