## ماذا ستتعلم؟

- مصطلحات **الأشجار**: الجذر، والورقة، والأب، والابن، والارتفاع.
- **قاعدة** شجرة البحث الثنائية، وكيف نبحث ونضيف فيها.
- **الحذف** بحالاته الثلاث، ومعنى «الخلف».
- طرق **التجوال** الأربع، ولماذا يعطي «بالترتيب» الأعداد مرتبة.
- لماذا تصبح الشجرة أحياناً **«عصا»** بطيئة، وكيف تحل **الأشجار المتوازنة** ذلك.

## الأشجار

<Concept term="الشجرة" en="Tree">

بنية بيانات **هرمية**: عقدة واحدة في الأعلى اسمها الجذر، ولكل عقدة أبناء، ولكل ابن أبناؤه... ولا توجد حلقات: من الجذر إلى أي عقدة طريق واحد فقط. مثل شجرة العائلة، أو المجلدات في حاسوبك.

**لماذا نستخدمها؟** لأن كثيراً من البيانات هرمية بطبيعتها، ولأن الشجرة المنظمة تسمح بالوصول إلى أي عنصر بخطوات قليلة: كل خطوة تنزل مستوى، والمستويات قليلة جداً.

**أين تُستخدم؟** في نظام الملفات، وصفحات الويب (كل صفحة شجرة من العناصر)، وفهارس قواعد البيانات، والمترجمات (تحوّل الكود إلى شجرة)، والذكاء الصنعي (أشجار القرار)، وألعاب الشطرنج.

</Concept>

| المصطلح | المعنى |
| --- | --- |
| **الجذر** | العقدة الأعلى، بلا أب |
| **الأب والابن** | العقدة وما يتفرع منها مباشرة |
| **الورقة** | عقدة بلا أبناء |
| **الشجرة الفرعية** | عقدة مع كل ما تحتها: هي شجرة أيضاً! |
| **العمق** | عدد الخطوات من الجذر إلى العقدة |
| **الارتفاع** | عدد المستويات في الشجرة كلها (أطول طريق من الجذر إلى ورقة) |

و<Term t="الشجرة الثنائية" en="Binary Tree" def="شجرة لكل عقدة فيها ابنان على الأكثر: ابن أيسر وابن أيمن." /> هي شجرة لكل عقدة فيها **ابنان على الأكثر**: أيسر وأيمن.

## قاعدة شجرة البحث

<Term t="شجرة البحث الثنائية" en="Binary Search Tree (BST)" def="شجرة ثنائية فيها قاعدة: كل ما في الفرع الأيسر لأي عقدة أصغر منها، وكل ما في الفرع الأيمن أكبر منها." /> شجرة ثنائية فيها قاعدة واحدة، تنطبق على **كل** عقدة:

> كل ما في الفرع **الأيسر** أصغر من العقدة، وكل ما في الفرع **الأيمن** أكبر منها.

هذه القاعدة وحدها تعطي البحث السريع: في كل عقدة نعرف أي فرع نترك، تماماً كالبحث الثنائي.

<BstLab />

**ماذا يجب أن ترى؟**

1. **ابحث عن 35:** الطريق البرتقالي 50 ← 30 ← 40 ← 35. أربع مقارنات، ولم ننظر إلى الفرع الأيمن (60، 70، 80) أبداً.
2. **ابحث عن 65:** ‏50 ← 70 ← 60، ثم مكان فارغ. فهو غير موجود.
3. **أضف 45:** يمشي في الطريق نفسه حتى يجد مكاناً فارغاً (يمين 40)، ويستقر هناك.
4. اضغط «شجرة جاهزة»، ثم **احذف 20، ثم 40، ثم 50 (الجذر):** ستمرّ على الحالات الثلاث للحذف، وسيصبح 60 هو الجذر الجديد.
5. **تجوال «بالترتيب»:** الأعداد تخرج مرتبة: 20، 30، 35، 40، 50، 60، 70، 80.
6. اضغط «أدخل 10، 20، ... 70 بالترتيب»: **عصا** ارتفاعها 7! ثم «القيم نفسها متوازنة»: ارتفاعها **3** فقط.

## البحث والإضافة

```python
class Node:
    def __init__(self, key):
        self.key = key
        self.left = self.right = None

def search(node, key):
    while node and node.key != key:
        node = node.left if key < node.key else node.right
    return node                       # None if not found

def insert(node, key):
    if node is None:
        return Node(key)              # found an empty spot
    if key < node.key:
        node.left = insert(node.left, key)
    elif key > node.key:
        node.right = insert(node.right, key)
    return node

root = None
for k in [50, 30, 70, 20, 40, 60, 80, 35]:
    root = insert(root, k)
print(search(root, 35) is not None)   # True
```

```cpp
struct Node {
    int key;
    Node *left = nullptr, *right = nullptr;
    Node(int k) : key(k) {}
};

Node* search(Node* node, int key) {
    while (node && node->key != key)
        node = key < node->key ? node->left : node->right;
    return node;
}

Node* insert(Node* node, int key) {
    if (!node) return new Node(key);
    if (key < node->key) node->left = insert(node->left, key);
    else if (key > node->key) node->right = insert(node->right, key);
    return node;
}
```

البحث والإضافة يمشيان طريقاً واحداً من الجذر إلى الأسفل، فزمنهما $O(h)$، حيث h **ارتفاع** الشجرة.

## الحذف: ثلاث حالات

| الحالة | ماذا نفعل | مثال في الشجرة الجاهزة |
| --- | --- | --- |
| **ورقة** | نزيلها مباشرة | حذف 20 |
| **ابن واحد** | نضع ابنها مكانها | حذف 40 (له ابن واحد: 35) |
| **ابنان** | نضع مكانها **خلفها**، ثم نحذف الخلف من مكانه القديم | حذف 30 ← خلفه 35 |

<Term t="الخلف" en="In-order Successor" def="أصغر عنصر أكبر من العقدة، وهو أقصى اليسار في فرعها الأيمن. نضعه مكان العقدة عند حذفها إذا كان لها ابنان." /> هو أصغر عدد أكبر من العقدة: نذهب إلى الفرع الأيمن، ثم يساراً حتى النهاية. ولماذا هو بالذات؟ لأنه أكبر من كل الفرع الأيسر، وأصغر من باقي الفرع الأيمن، فيحافظ على القاعدة. والخلف ليس له ابن أيسر أبداً، فحذفه من مكانه القديم سهل (حالة 1 أو 2).

## طرق التجوال الأربع

<Term t="التجوال" en="Traversal" def="المرور على كل عقد الشجرة مرة واحدة بترتيب معيّن." /> هو المرور على كل العقد مرة واحدة. والفرق بين الطرق هو: **متى** نزور العقدة نفسها؟

| الطريقة | الترتيب | للشجرة الجاهزة | الاستخدام |
| --- | --- | --- | --- |
| **بالترتيب** | يسار، عقدة، يمين | 20 30 35 40 50 60 70 80 | الأعداد **مرتبة** |
| **قبلي** | عقدة، يسار، يمين | 50 30 20 40 35 70 60 80 | نسخ الشجرة، وحفظها في ملف |
| **بعدي** | يسار، يمين، عقدة | 20 35 40 30 60 80 70 50 | حذف الشجرة، وحساب حجم المجلدات |
| **مستوى مستوى** | من الأعلى، سطراً سطراً | 50 30 70 20 40 60 80 35 | أقرب العقد إلى الجذر أولاً |

```python
from collections import deque

def inorder(node, out):           # left, node, right
    if node:
        inorder(node.left, out)
        out.append(node.key)
        inorder(node.right, out)

def level_order(root):            # uses a queue, not recursion
    out, q = [], deque([root] if root else [])
    while q:
        node = q.popleft()
        out.append(node.key)
        if node.left:  q.append(node.left)
        if node.right: q.append(node.right)
    return out
```

```cpp
void inorder(Node* node, vector<int>& out) {
    if (!node) return;
    inorder(node->left, out);
    out.push_back(node->key);
    inorder(node->right, out);
}

vector<int> levelOrder(Node* root) {
    vector<int> out;
    queue<Node*> q;
    if (root) q.push(root);
    while (!q.empty()) {
        Node* n = q.front(); q.pop();
        out.push_back(n->key);
        if (n->left) q.push(n->left);
        if (n->right) q.push(n->right);
    }
    return out;
}
```

لاحظ: التجوال بالترتيب يعطي ترتيباً بزمن $O(n)$، بعد أن بنينا الشجرة. وهذه فكرة **الترتيب بالشجرة**.

## العصا والشجرة المتوازنة

كل العمليات $O(h)$. فكم ارتفاع الشجرة؟ **يعتمد على ترتيب الإدخال**:

- إذا أدخلنا أعداداً **عشوائية**، يكون الارتفاع قريباً من $\log_2 n$. مليون عقدة ← قرابة 20 إلى 50 مستوى.
- إذا أدخلنا أعداداً **مرتبة**، يذهب كل عدد يميناً، فتصبح الشجرة قائمة مرتبطة («عصا»)، والارتفاع n. مليون عقدة ← مليون مستوى!

| | **شجرة متوازنة** | **عصا** |
| --- | --- | --- |
| ارتفاع 7 عقد | 3 | 7 |
| ارتفاع 15 عقدة | 4 | 15 |
| ارتفاع مليون عقدة | 20 | 1,000,000 |
| البحث | $O(\log n)$ | $O(n)$ |

### الأشجار ذاتية التوازن

الحل: شجرة **تعيد توازنها بنفسها** بعد كل إضافة وحذف، فيبقى ارتفاعها $O(\log n)$ دائماً. والأداة الأساسية هي <Term t="التدوير" en="Rotation" def="عملية تعيد ترتيب عقدتين وأبنائهما في الشجرة، فترفع إحداهما وتُنزل الأخرى، مع الحفاظ على قاعدة شجرة البحث. تُستخدم لإعادة التوازن." />: نرفع ابناً مكان أبيه، وننزل الأب ليصبح ابنه، مع الحفاظ على القاعدة. مثلاً إذا أصبح عندنا 10 ← 20 ← 30 (عصا صغيرة)، ندوّر فيصبح 20 جذراً، و 10 يساره، و 30 يمينه.

| الشجرة | فكرتها | تُستخدم في |
| --- | --- | --- |
| <Term t="AVL" en="Adelson-Velsky and Landis Tree" def="أول شجرة بحث ذاتية التوازن (1962): الفرق بين ارتفاع الفرعين الأيسر والأيمن لأي عقدة لا يزيد عن 1." /> | فرق ارتفاع الفرعين لأي عقدة لا يزيد عن 1 | قواعد بيانات تحتاج بحثاً سريعاً جداً |
| <Term t="الشجرة الحمراء السوداء" en="Red-Black Tree" def="شجرة بحث ذاتية التوازن تلوّن العقد بالأحمر والأسود وتتبع قواعد ألوان تضمن أن أطول طريق لا يتجاوز ضعف أقصر طريق." /> | تلوين العقد بقواعد تضمن توازناً تقريبياً | `std::map` و `std::set` في C++، و `TreeMap` في Java، ونواة لينكس |
| <Term t="B-Tree" en="B-Tree" def="شجرة متوازنة لكل عقدة فيها أبناء كثيرون (مئات أحياناً)، فيكون ارتفاعها صغيراً جداً، مناسبة للقرص الصلب وقواعد البيانات." /> | أبناء كثيرون لكل عقدة، فالارتفاع صغير جداً | فهارس كل قواعد البيانات تقريباً، وأنظمة الملفات |

## الشجرة أم التجزئة؟

| | **جدول التجزئة** | **شجرة متوازنة** |
| --- | --- | --- |
| بحث، إضافة، حذف | $O(1)$ في المتوسط | $O(\log n)$ مضمون |
| المفاتيح مرتبة؟ | لا | نعم |
| أصغر وأكبر عنصر | $O(n)$ | $O(\log n)$ |
| كل المفاتيح بين a و b | $O(n)$ | $O(\log n + k)$ |
| أسوأ حالة | $O(n)$ | $O(\log n)$ |

## الخلاصة

- **الشجرة**: جذر، وأبناء، وأوراق، ولا حلقات. والارتفاع يحدد سرعة كل شيء.
- **شجرة البحث الثنائية**: اليسار أصغر، واليمين أكبر، في كل عقدة.
- البحث والإضافة والحذف $O(h)$. والحذف له ثلاث حالات، وأصعبها نحلها **بالخلف**.
- **التجوال بالترتيب** يعطي المفاتيح مرتبة. والقبلي والبعدي ومستوى مستوى لاستخدامات أخرى.
- الإدخال المرتب يصنع **عصا** $O(n)$. و**الأشجار ذاتية التوازن** (AVL، والحمراء السوداء، و B-Tree) تضمن $O(\log n)$ بالتدوير.

<details class="answer">
<summary>ارسم الشجرة الناتجة عن إدخال 8، 3، 10، 1، 6، 14، 4، 7، 13 بالترتيب، وما ارتفاعها؟</summary>

الجذر 8. يساره 3 (يسار 3 هو 1، ويمينه 6، ويسار 6 هو 4 ويمينه 7). يمين 8 هو 10، ويمين 10 هو 14، ويسار 14 هو 13. الارتفاع 4 (مثلاً 8 ← 3 ← 6 ← 4).
</details>

<details class="answer">
<summary>في الشجرة السابقة، احذف 3. ماذا يحدث؟</summary>

3 له ابنان، فنضع مكانه خلفه: أصغر عدد في فرعه الأيمن، أي نذهب إلى 6 ثم يساراً إلى 4. فيصبح 4 مكان 3، ونحذف 4 من مكانه القديم (كان ورقة).
</details>

<details class="answer">
<summary>لماذا يعطي التجوال بالترتيب الأعداد مرتبة؟</summary>

لأنه يزور كل الفرع الأيسر (الأصغر) قبل العقدة، وكل الفرع الأيمن (الأكبر) بعدها. وهذا ينطبق على كل عقدة، فالنتيجة مرتبة تماماً.
</details>

<details class="answer">
<summary>كم أقل ارتفاع ممكن لشجرة ثنائية فيها 1000 عقدة؟</summary>

10، لأن شجرة ارتفاعها h تحمل على الأكثر 2ʰ − 1 عقدة، و 2¹⁰ − 1 = 1023 ≥ 1000، بينما 2⁹ − 1 = 511 لا تكفي.
</details>

<details class="answer">
<summary>متى نفضّل شجرة البحث المتوازنة على جدول التجزئة؟</summary>

عندما نحتاج الترتيب: طباعة المفاتيح مرتبة، أو البحث عن مدى، أو أصغر وأكبر عنصر، أو أقرب مفتاح. وعندما نحتاج ضماناً لأسوأ حالة O(log n).
</details>
