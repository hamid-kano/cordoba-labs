تخيّل أن الطرق أنابيب ماء، وأنك تفتح صنبوراً في دمشق. ينتشر الماء في كل الأنابيب بالسرعة نفسها. أي مدينة يصلها الماء **أولاً**؟ الأقرب طبعاً. ثم التي بعدها. وفي اللحظة التي يصل فيها الماء إلى مدينة، نعرف أقصر طريق إليها: إنه الطريق الذي سلكه الماء. هذا بالضبط ما تفعله خوارزمية **Dijkstra**، دون ماء.

## ماذا ستتعلم؟

- لماذا لا يكفي البحث بالعرض عندما تختلف أطوال الطرق.
- فكرة **الإرخاء**: تحسين المسافة المعروفة كلما وجدنا طريقاً أقصر.
- خوارزمية **Dijkstra** خطوة خطوة، ولماذا هي صحيحة.
- تنفيذها بـ**طابور أولوية**، وتعقيدها.
- لماذا **تفشل** مع الأوزان السالبة، وما البديل.
- خوارزميات قريبة: **A\*** في الخرائط والألعاب، و **Floyd-Warshall** لكل الأزواج.

## المسألة

في [الصفحة السابقة](../graphs-bfs-dfs/) وجد البحث بالعرض أقصر طريق **بعدد الأضلاع**. لكن في الخريطة، طريق من 3 مدن قد يكون أقصر من طريق من مدينتين، إذا كانت أطواله أقل. نحتاج خوارزمية تهتم **بالأوزان**.

<Concept term="أقصر طريق" en="Shortest Path">

في رسم موزون، أقصر طريق بين عقدتين هو الطريق الذي **مجموع أوزان أضلاعه** أقل ما يمكن. والوزن قد يكون مسافة، أو زمناً، أو كلفة، أو حتى احتمال فشل.

**لماذا نحتاجه؟** لأن كل تطبيق ملاحة يسأله ملايين المرات يومياً: «ما أسرع طريق إلى العمل الآن؟». وشبكة الإنترنت تسأله لترسل كل رسالة عبر أسرع مسار.

**أين يُستخدم؟** خرائط الهاتف، وتوجيه الحزم في الإنترنت (بروتوكول <Term t="OSPF" en="Open Shortest Path First" def="بروتوكول تستخدمه أجهزة التوجيه في الشبكات لتحسب أقصر مسار للرسائل، ويعتمد على خوارزمية Dijkstra." />)، وشركات الشحن والتوصيل، والألعاب، وحتى تحويل الكلام إلى نص.

</Concept>

## الإرخاء

الفكرة الأساسية في كل خوارزميات أقصر طريق اسمها <Term t="الإرخاء" en="Relaxation" def="فحص ضلع من u إلى v: إذا كانت مسافة u زائد طول الضلع أقل من مسافة v المعروفة، نحدّث مسافة v ونسجّل أننا نصل إليها من u." />. لكل مدينة نحفظ **أقصر مسافة عرفناها حتى الآن**، ونبدأ بـ ∞ (لا نعرف أي طريق). ثم لكل طريق من u إلى v نسأل:

$$
\text{if } d[u] + w(u, v) < d[v] \text{ then } d[v] \leftarrow d[u] + w(u, v)
$$

بالكلام: «إذا كان الذهاب إلى v **عبر u** أقصر مما نعرف، فهذا طريق أفضل إلى v». ونسجّل أن أفضل طريق إلى v يأتي من u.

## خوارزمية Dijkstra

نشرها العالم الهولندي <Term t="Edsger Dijkstra" en="Edsger W. Dijkstra" def="عالم حاسوب هولندي، اخترع خوارزمية أقصر طريق عام 1956، وقال إنه صممها في عشرين دقيقة في مقهى دون ورقة وقلم." /> عام 1959، وتقول القصة إنه صممها في عشرين دقيقة في مقهى، دون ورقة وقلم. الخطوات:

1. مسافة البداية 0، وكل الباقي ∞.
2. اختر **أقرب** مدينة لم ننتهِ منها. مسافتها الآن **نهائية**.
3. **أرخِ** كل الطرق الخارجة منها.
4. كرّر حتى ننتهي من كل المدن.

<DijkstraLab />

**ماذا يجب أن ترى؟**

1. أول مدينة نختارها بعد دمشق هي **درعا** (100)، لأنها الأقرب. ثم **حمص** (160)، ثم **حماة** (207).
2. تعرف الخوارزمية أولاً طريقاً إلى اللاذقية عبر حماة طوله **357**، ثم تجد عبر طرطوس طريقاً أقصر طوله **345**، فتتحدّث المسافة (بنفسجي).
3. بعض الإرخاءات تفشل (أحمر متقطع): من دير الزور إلى الرقة 580، وهذا أطول من **542** المعروف عبر حلب.
4. في النهاية اضغط على أي مدينة: يظهر طريقها البرتقالي.

### لماذا هي صحيحة؟

السر في الخطوة 2: عندما نختار **أقرب** مدينة غير منتهية، لا يمكن أن يوجد طريق أقصر إليها لم نكتشفه. لأن أي طريق آخر يجب أن يمر بمدينة غير منتهية، وكل هذه المدن **أبعد** منها أصلاً، والطرق لا تُنقص المسافة (أوزانها موجبة). لذلك تُسمّى Dijkstra خوارزمية <Term t="جشعة" en="Greedy" def="خوارزمية تأخذ في كل خطوة الخيار الذي يبدو الأفضل الآن، دون أن ترجع عنه أبداً." />: تأخذ الأقرب دائماً، ولا ترجع عن قرارها (سترى الخوارزميات الجشعة بالتفصيل في الصفحة 15).

## في الكود

نحتاج في كل خطوة «أقرب مدينة غير منتهية». وهذا بالضبط ما يعطيه **طابور الأولوية** من [الصفحة العاشرة](../heap/):

<TabItem label="Python">

```python
import heapq

roads = {
    "Damascus": [("Homs", 160), ("Palmyra", 230), ("Daraa", 100)],
    "Homs": [("Damascus", 160), ("Hama", 47), ("Tartus", 95), ("Palmyra", 155)],
    "Hama": [("Homs", 47), ("Aleppo", 145), ("Latakia", 150)],
    # ... the rest of the map
}

def dijkstra(graph, src):
    dist = {src: 0}
    prev = {src: None}
    pq = [(0, src)]                          # (distance, city)
    done = set()
    while pq:
        d, u = heapq.heappop(pq)             # the closest unfinished city
        if u in done:
            continue                         # an old, longer entry
        done.add(u)
        for v, w in graph.get(u, []):
            nd = d + w
            if nd < dist.get(v, float("inf")):   # relax
                dist[v] = nd
                prev[v] = u
                heapq.heappush(pq, (nd, v))
    return dist, prev

def path(prev, t):
    out = []
    while t is not None:
        out.append(t)
        t = prev[t]
    return out[::-1]
```

<TabItem label="C++">

```cpp
#include <queue>
using Edge = pair<int, int>;                 // (neighbor, weight)

vector<long long> dijkstra(const vector<vector<Edge>>& g, int src, vector<int>& prev) {
    const long long INF = 1e18;
    vector<long long> dist(g.size(), INF);
    prev.assign(g.size(), -1);
    priority_queue<pair<long long,int>, vector<pair<long long,int>>, greater<>> pq;
    dist[src] = 0;
    pq.push({0, src});
    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d > dist[u]) continue;           // an old, longer entry
        for (auto [v, w] : g[u])
            if (d + w < dist[v]) {           // relax
                dist[v] = d + w;
                prev[v] = u;
                pq.push({dist[v], v});
            }
    }
    return dist;
}
```

**التعقيد:** كل ضلع قد يضيف عنصراً إلى الطابور، وكل إضافة أو إخراج $O(\log V)$. فالمجموع $O((V + E) \log V)$. مع خريطة دولة فيها مليون تقاطع، هذا ثوانٍ قليلة. (وتطبيقات الخرائط الحقيقية تضيف حيلاً تجعلها أسرع بآلاف المرات، مثل حساب أجزاء من الطرق مسبقاً).

## عندما تفشل: الأوزان السالبة

ماذا لو كان لطريق وزن **سالب**؟ مثلاً: في تطبيق عملات، تحويل يربحك مالاً بدل أن يكلّفك. عندها تفشل Dijkstra، لأن فكرتها كلها «الطرق لا تُنقص المسافة». قد تعلن مسافة مدينة نهائية، ثم يظهر لاحقاً طريق أقصر عبر ضلع سالب.

البديل: خوارزمية <Term t="Bellman-Ford" en="Bellman-Ford Algorithm" def="خوارزمية أقصر طريق تعمل مع الأوزان السالبة: ترخي كل الأضلاع V − 1 مرة، وتكتشف الحلقات السالبة. زمنها O(V × E)." />: ترخي **كل** الأضلاع، ثم تكرر ذلك $V - 1$ مرة. أبطأ ($O(V \times E)$)، لكنها تعمل مع الأوزان السالبة، وتكتشف أيضاً <Term t="الحلقة السالبة" en="Negative Cycle" def="حلقة مجموع أوزانها سالب، فكلما درنا فيها نقصت المسافة، فلا يوجد أقصر طريق أصلاً." />: حلقة كلما درنا فيها نقصت المسافة، فلا يوجد «أقصر طريق» أصلاً. وفي أسواق العملات، الحلقة السالبة تعني فرصة ربح مضمونة!

## خوارزميات قريبة

| الخوارزمية | تحل | الأوزان | الزمن |
| --- | --- | --- | --- |
| البحث بالعرض | من مصدر واحد | بلا أوزان (كلها 1) | $O(V + E)$ |
| **Dijkstra** | من مصدر واحد إلى الكل | موجبة فقط | $O((V + E) \log V)$ |
| **Bellman-Ford** | من مصدر واحد إلى الكل | تقبل السالبة | $O(V \cdot E)$ |
| **A\*** | من مصدر إلى هدف واحد | موجبة، مع تقدير ذكي للباقي | أسرع من Dijkstra عملياً |
| **Floyd-Warshall** | بين **كل** الأزواج | تقبل السالبة | $O(V^3)$ |

<Term t="A*" en="A-star Search" def="تحسين لخوارزمية Dijkstra نحو هدف واحد: تختار العقدة التي مسافتها من البداية زائد تقدير مسافتها إلى الهدف أقل، فتتجه نحو الهدف بدل أن تنتشر في كل الاتجاهات." /> هي Dijkstra مع **بوصلة**: بدل أن تختار الأقرب إلى البداية فقط، تختار الأقل في (المسافة من البداية + **تقدير** المسافة الباقية إلى الهدف، مثل المسافة بخط مستقيم). فلا تضيّع الوقت في المدن التي في الاتجاه المعاكس. وهي الخوارزمية التي تحرّك الشخصيات في أغلب ألعاب الفيديو.

و <Term t="Floyd-Warshall" en="Floyd-Warshall Algorithm" def="خوارزمية تحسب أقصر مسافة بين كل زوجين من العقد بثلاث حلقات متداخلة، وتجرّب كل عقدة كمحطة وسيطة." /> تجرّب كل مدينة k كـ«محطة وسيطة» بين كل زوجين i و j، بثلاث حلقات قصيرة جداً:

```text
for k in nodes:
    for i in nodes:
        for j in nodes:
            d[i][j] = min(d[i][j], d[i][k] + d[k][j])
```

## الخلاصة

- **أقصر طريق** في رسم موزون: أقل مجموع أوزان.
- **الإرخاء**: إذا كان الطريق عبر u أقصر، نحدّث مسافة v ونسجّل أننا نصل إليها من u.
- **Dijkstra**: اختر الأقرب غير المنتهي، فمسافته نهائية، ثم أرخِ طرقه. $O((V + E) \log V)$ بطابور أولوية.
- تفشل مع **الأوزان السالبة**، والبديل **Bellman-Ford**، الذي يكتشف الحلقات السالبة أيضاً.
- **A\*** نحو هدف واحد بتقدير ذكي، و **Floyd-Warshall** لكل الأزواج $O(V^3)$.

<details class="answer">
<summary>أعط مثالاً صغيراً تفشل فيه Dijkstra بسبب وزن سالب.</summary>

ثلاث عقد: من A إلى B بوزن 2، ومن A إلى C بوزن 5، ومن C إلى B بوزن −4. تختار Dijkstra B أولاً (2) وتعلنها نهائية. لكن الطريق A ← C ← B طوله 5 − 4 = 1، وهو أقصر.

<details class="answer">
<summary>ما الفرق بين Dijkstra و A*؟</summary>

Dijkstra تختار العقدة الأقرب إلى البداية، فتنتشر في كل الاتجاهات. أما A* فتختار العقدة التي (مسافتها من البداية + تقدير مسافتها إلى الهدف) أقل، فتتجه نحو الهدف وتزور عقداً أقل. وإذا كان التقدير صفراً دائماً، تصبح A* هي Dijkstra نفسها.
</details>
