## ماذا ستتعلم؟

- ما هو **طابور الأولوية**، ولماذا لا تكفي القائمة المرتبة.
- **الكومة**: شجرة بقاعدة بسيطة، الأب أهم من ابنيه.
- الحيلة الذكية: حفظ الشجرة في **مصفوفة** دون أي مؤشرات.
- **الطفو** عند الإضافة، و**النزول** عند الإخراج.
- **بناء الكومة** بزمن خطي، و**ترتيب الكومة**.
- تطبيقات مشهورة: أكبر k عناصر، وجدولة المهام، وأقصر طريق.

## طابور الأولوية

<Concept term="طابور الأولوية" en="Priority Queue">

بنية نضيف إليها عناصر لكل منها **أولوية**، ونخرج منها دائماً العنصر **الأعلى أولوية**، لا الأقدم. مثل قسم الإسعاف، أو بوابة المطار التي يدخل منها أصحاب الحاجات الخاصة أولاً.

**لماذا نستخدمه؟** لأن مسائل كثيرة تسأل مرة بعد مرة: «ما الأهم الآن؟» بينما تصل عناصر جديدة باستمرار. ونريد الجواب سريعاً في كل مرة.

**أين يُستخدم؟** نظام التشغيل يختار المهمة الأهم ليعطيها المعالج، والخرائط تختار أقرب مدينة لم تزرها بعد (خوارزمية Dijkstra)، وضغط الملفات (ترميز هوفمان)، والألعاب، والمحاكاة.

</Concept>

ما البنية المناسبة؟ لنقارن:

| البنية | إضافة | إخراج الأعلى |
| --- | --- | --- |
| قائمة غير مرتبة | $O(1)$ | $O(n)$: نبحث في الكل |
| قائمة مرتبة | $O(n)$: نجد المكان ونزيح | $O(1)$ |
| **الكومة** | $O(\log n)$ | $O(\log n)$ |

الكومة لا تختار طرفاً: كلتا العمليتين سريعتان. ومع مليون عملية، الفرق بين $O(n)$ و $O(\log n)$ هو الفرق بين ساعات وثوانٍ.

## الكومة

<Term t="الكومة العظمى" en="Max-Heap" def="شجرة ثنائية كاملة، كل أب فيها أكبر من ابنيه أو يساويهما، فيكون أكبر عنصر دائماً في الجذر." /> شجرة ثنائية لها شرطان:

1. **شرط الشكل:** الشجرة <Term t="كاملة" en="Complete Binary Tree" def="شجرة ثنائية كل مستوياتها ممتلئة إلا الأخير، والأخير يمتلئ من اليسار إلى اليمين دون فراغات." />: كل المستويات ممتلئة إلا الأخير، والأخير يمتلئ من اليسار دون فراغات. فارتفاعها دائماً $\lfloor \log_2 n \rfloor + 1$.
2. **شرط الترتيب:** كل أب **أكبر من ابنيه** أو يساويهما.

لاحظ أن الشرط الثاني أضعف بكثير من شجرة البحث: لا يهمنا من الأكبر بين الأخوين، ولا ترتيب الفروع. يهمنا فقط أن الأكبر **دائماً في الجذر**. وهذا يكفي!

وهناك أيضاً <Term t="الكومة الصغرى" en="Min-Heap" def="مثل الكومة العظمى لكن بالعكس: كل أب أصغر من ابنيه، فيكون أصغر عنصر في الجذر." />: كل أب **أصغر** من ابنيه، فالأصغر في الجذر.

**ماذا يجب أن ترى؟**

1. أضف مريضاً بخطورة **95**: يوضع في آخر مكان (بنفسجي)، ثم **يطفو** إلى الأعلى بتبادله مع أبيه مرتين، حتى يصبح الجذر.
2. اضغط «عالج الأخطر»: يخرج 95 من الجذر، ويصعد آخر مريض إلى الجذر، ثم **ينزل** بتبادله مع أخطر ابنيه، حتى يستقر.
3. لاحظ الصف تحت الشجرة: **الشجرة نفسها محفوظة في مصفوفة**، والأرقام الصغيرة هي رقم الخانة.
4. اضغط «عالج الجميع بالترتيب»: يخرج المرضى من الأخطر إلى الأقل، **مرتبين**.

## الشجرة داخل مصفوفة

لأن الكومة شجرة **كاملة** دون فراغات، نستطيع أن نحفظها في مصفوفة مستوى بعد مستوى، دون أي مؤشرات! فالعقدة في الخانة i:

| | رقم الخانة (يبدأ من 0) |
| --- | --- |
| الابن الأيسر | $2i + 1$ |
| الابن الأيمن | $2i + 2$ |
| الأب | $\lfloor (i - 1) / 2 \rfloor$ |

في الكومة `[90, 70, 40, 10, 20, 30]`: ابنا 70 (الخانة 1) في الخانتين 3 و 4، أي 10 و 20. وأبو 30 (الخانة 5) في الخانة 2، أي 40. هذا يوفّر الذاكرة، ويجعل الكومة سريعة جداً لأن عناصرها متجاورة.

## الطفو والنزول

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
class MaxHeap:
    def __init__(self):
        self.a = []

    def push(self, x):                       # O(log n)
        a = self.a
        a.append(x)                          # 1. put it at the end
        i = len(a) - 1
        while i > 0:                         # 2. sift up
            p = (i - 1) // 2
            if a[p] >= a[i]:
                break
            a[p], a[i] = a[i], a[p]
            i = p

    def pop(self):                           # O(log n)
        a = self.a
        top = a[0]
        last = a.pop()
        if a:
            a[0] = last                      # 1. last item to the root
            i = 0
            while True:                      # 2. sift down
                l, r, m = 2 * i + 1, 2 * i + 2, i
                if l < len(a) and a[l] > a[m]: m = l
                if r < len(a) and a[r] > a[m]: m = r
                if m == i:
                    break
                a[i], a[m] = a[m], a[i]
                i = m
        return top
```

<TabItem label="C++">

```cpp
struct MaxHeap {
    vector<int> a;

    void push(int x) {                       // O(log n)
        a.push_back(x);
        int i = a.size() - 1;
        while (i > 0) {
            int p = (i - 1) / 2;
            if (a[p] >= a[i]) break;
            swap(a[p], a[i]);
            i = p;
        }
    }

    int pop() {                              // O(log n)
        int top = a[0];
        a[0] = a.back();
        a.pop_back();
        int i = 0, n = a.size();
        while (true) {
            int l = 2 * i + 1, r = l + 1, m = i;
            if (l < n && a[l] > a[m]) m = l;
            if (r < n && a[r] > a[m]) m = r;
            if (m == i) break;
            swap(a[i], a[m]);
            i = m;
        }
        return top;
    }
};
```

## بناء الكومة بزمن خطي

لو كان عندنا n عنصر دفعة واحدة، يمكن أن نضيفها واحداً واحداً بـ $O(n \log n)$. لكن هناك طريقة أسرع: نضعها كلها في المصفوفة كما هي، ثم **ننزل** كل عقدة من آخر أب إلى الجذر. ويُسمّى هذا <Term t="بناء الكومة" en="Heapify" def="تحويل مصفوفة عادية إلى كومة بإنزال كل عقدة أب من الأسفل إلى الأعلى، بزمن O(n)." />.

ولماذا هو $O(n)$؟ لأن **نصف** العقد أوراق لا تنزل أبداً، وربعها ينزل مستوى واحداً فقط، وثمنها مستويين... والعقد التي تنزل كثيراً قليلة جداً (الجذر وحده ينزل $\log n$). والمجموع:

$$
\frac{n}{4} \cdot 1 + \frac{n}{8} \cdot 2 + \frac{n}{16} \cdot 3 + \dots < n
$$

## ترتيب الكومة

إذا أخرجنا كل العناصر من كومة عظمى، تخرج من الأكبر إلى الأصغر: هذا ترتيب! وهو <Term t="ترتيب الكومة" en="Heapsort" def="ترتيب يبني كومة عظمى من المصفوفة، ثم يكرر: يبدّل الجذر (الأكبر) مع آخر عنصر، ويصغّر الكومة، وينزل الجذر الجديد." />، وأجمل ما فيه أنه يعمل **في المكان**: نبدّل الجذر مع آخر خانة في الكومة، ونصغّر الكومة خانة، ونُنزل الجذر الجديد. فتتجمع الأعداد الكبيرة مرتبة في آخر المصفوفة.

| | **ترتيب الكومة** | الدمج | السريع |
| --- | --- | --- | --- |
| أسوأ حالة | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| ذاكرة إضافية | $O(1)$ | $O(n)$ | $O(\log n)$ |
| ثابت؟ | لا | نعم | لا |

ترتيب الكومة يجمع الضمان والمكان، لكنه عملياً أبطأ قليلاً من السريع لأنه يقفز في الذاكرة. لذلك تستخدمه C++ **احتياطاً** داخل `std::sort` إذا تعمّقت عودية السريع أكثر من اللازم.

## في الكود الحقيقي

<TabItem label="Python">

```python
import heapq                      # a MIN-heap on a normal list

h = []
for x in [40, 20, 70, 10, 90, 30]:
    heapq.heappush(h, x)
print(heapq.heappop(h))           # 10  (the smallest)

# max-heap trick: store negatives
mh = []
for x in [40, 20, 70]:
    heapq.heappush(mh, -x)
print(-heapq.heappop(mh))         # 70

# (priority, name) pairs: compared by priority first
er = []
heapq.heappush(er, (-90, "Sami"))
heapq.heappush(er, (-30, "Reem"))
print(heapq.heappop(er)[1])       # Sami

a = [5, 2, 8, 1]
heapq.heapify(a)                  # O(n) build
print(heapq.nlargest(2, [5, 2, 8, 1, 9]))   # [9, 8]
```

#include <queue>

priority_queue<int> pq;                 // a MAX-heap by default
for (int x : {40, 20, 70, 10, 90, 30}) pq.push(x);
cout << pq.top(); pq.pop();             // 90

priority_queue<int, vector<int>, greater<int>> minq;   // min-heap
minq.push(40); minq.push(20);
cout << minq.top();                     // 20

priority_queue<pair<int, string>> er;   // compared by .first

## تطبيق مشهور: أكبر k عناصر

عندنا مليار رقم (مثلاً عدد مشاهدات كل فيديو)، ونريد **أكبر 10** فقط. ترتيب المليار مكلف جداً. الحيلة: نحفظ **كومة صغرى** فيها 10 عناصر فقط. نمرّ على الأرقام، وكل رقم أكبر من أصغر ما في الكومة (الجذر) يأخذ مكانه. في النهاية، الكومة فيها أكبر 10.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
import heapq

def top_k(numbers, k):
    h = []                                   # min-heap of size k
    for x in numbers:
        if len(h) < k:
            heapq.heappush(h, x)
        elif x > h[0]:                       # beats the smallest of the top k
            heapq.heapreplace(h, x)
    return sorted(h, reverse=True)

print(top_k([5, 1, 9, 3, 7, 6, 8, 2], 3))   # [9, 8, 7]
```

</TabItem>
<TabItem label="C++">

```cpp
vector<int> topK(const vector<int>& nums, int k) {
    priority_queue<int, vector<int>, greater<int>> h;   // min-heap
    for (int x : nums) {
        if ((int)h.size() < k) h.push(x);
        else if (x > h.top()) { h.pop(); h.push(x); }
    }
    vector<int> out;
    while (!h.empty()) { out.push_back(h.top()); h.pop(); }
    reverse(out.begin(), out.end());
    return out;
}
```

</TabItem>
</Tabs>

## الخلاصة

- **طابور الأولوية**: نخرج دائماً الأعلى أولوية. والكومة تعطي الإضافة والإخراج بـ $O(\log n)$.
- **الكومة العظمى**: شجرة كاملة، وكل أب أكبر من ابنيه، فالأكبر في الجذر.
- تُحفظ في **مصفوفة**: الابنان $2i + 1$ و $2i + 2$، والأب $\lfloor (i-1)/2 \rfloor$.
- الإضافة: في الآخر ثم **طفو**. والإخراج: الآخر إلى الجذر ثم **نزول**.
- **بناء الكومة** $O(n)$، و**ترتيب الكومة** $O(n \log n)$ في المكان، لكنه غير ثابت.
- `heapq` كومة **صغرى**، و `priority_queue` كومة **عظمى**. وأكبر k عناصر بكومة صغرى حجمها k.

<details class="answer">
<summary>لماذا نحفظ الكومة في مصفوفة، ولا نحفظ شجرة البحث في مصفوفة بالطريقة نفسها؟</summary>

لأن الكومة شجرة كاملة دائماً، بلا فراغات، فتمتلئ المصفوفة دون خانات ضائعة. أما شجرة البحث فقد تكون غير متوازنة (مثل العصا)، فتحتاج مصفوفة ضخمة أغلب خاناتها فارغة.
</details>

<details class="answer">
<summary>كيف تستخدم heapq في Python ككومة عظمى؟</summary>

نضيف سالب كل عدد: `heappush(h, -x)`، ثم نخرج ونعكس الإشارة: `-heappop(h)`. فالعدد الأكبر يصبح الأصغر بعد السالب، ويخرج أولاً.
</details>

<details class="answer">
<summary>لماذا نستخدم كومة صغرى (لا عظمى) لإيجاد أكبر k عناصر؟</summary>

لأننا نحتاج أن نعرف بسرعة **أضعف** عنصر بين الـ k الحاليين، لنقرر هل الرقم الجديد يستحق مكانه. والكومة الصغرى تضع الأضعف في الجذر.
</details>
