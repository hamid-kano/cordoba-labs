<Aside type="tip" title="الفكرة ببساطة">
عندما يوزّع الأستاذ أوراق الامتحان مرتبة أبجدياً، يجد كل طالب ورقته بسرعة. وعندما ترتّب أوراق اللعب في يدك، تعرف فوراً ماذا تملك. **الترتيب** يجعل كل شيء بعده أسهل: البحث، وإيجاد المكرر، وإيجاد الأكبر والأصغر. لذلك هو من أكثر العمليات استخداماً في الحاسوب.
</Aside>

## ماذا ستتعلم؟

- لماذا نرتّب، وماذا نقيس في خوارزمية الترتيب.
- ثلاث خوارزميات بسيطة: **الفقاعي**، و**الاختيار**، و**الإدراج**، خطوة خطوة.
- معنى **الانقلابات**، ولماذا عددها يساوي تبديلات الفقاعي.
- صفتان مهمتان: **الثبات**، و**الترتيب في المكان**.
- متى نستخدم كل خوارزمية، ولماذا كلها $O(n^2)$.

## ماذا نقيس في الترتيب؟

<Concept term="الترتيب" en="Sorting">

**إعادة ترتيب عناصر قائمة بحسب قاعدة**، غالباً من الأصغر إلى الأكبر. ويمكن أن نرتّب أي شيء نستطيع أن نقارن بينه: أرقاماً، وأسماءً، وتواريخ، وطلاباً بحسب معدلهم.

**لماذا نستخدمه؟** لأن القائمة المرتبة تسمح بالبحث الثنائي، وتجعل المكرر متجاوراً، وتعطي الأكبر والأصغر فوراً، وتسهّل على الإنسان القراءة.

**أين يُستخدم؟** في كل مكان: ترتيب نتائج البحث، وقائمة الأغاني، وجدول العلامات، ورسائل البريد حسب التاريخ، وقواعد البيانات قبل كثير من العمليات.

</Concept>

نقيس كل خوارزمية ترتيب بشيئين:

- **عدد المقارنات:** كم مرة سألنا «أيهما أكبر؟».
- **عدد التبديلات:** كم مرة حرّكنا عناصر. والتحريك قد يكون مكلفاً إذا كانت العناصر كبيرة (مثل ملفات).

## الترتيب الفقاعي

نمرّ على القائمة، ونقارن كل **جارين**: إذا كانا بالترتيب الخاطئ نبدّلهما. بعد أول جولة، يصل **أكبر** عنصر إلى آخر القائمة، كأنه فقاعة تطفو إلى السطح. ثم نكرر للباقي. ويُسمّى <Term t="الترتيب الفقاعي" en="Bubble Sort" def="ترتيب يقارن كل عنصرين متجاورين ويبدّلهما إذا كانا بالترتيب الخاطئ، فيطفو أكبر عنصر إلى النهاية في كل جولة." />.

<SortLab algo="bubble" lock />

**ماذا يجب أن ترى؟** في الجولة الأولى يتحرك 9 نحو اليمين خطوة خطوة حتى يصل إلى الآخر ويصبح أخضر. ثم 8، وهكذا. ومع «مرتب أصلاً» ينتهي بعد جولة واحدة فقط (7 مقارنات)، لأنه لم يبدّل شيئاً.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def bubble_sort(a):
    n = len(a)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):        # the last i items are already in place
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:                   # no swap in a full pass: done
            break
    return a
```

</TabItem>
<TabItem label="C++">

```cpp
void bubbleSort(vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;
        for (int j = 0; j < n - 1 - i; j++)
            if (a[j] > a[j + 1]) {
                swap(a[j], a[j + 1]);
                swapped = true;
            }
        if (!swapped) break;
    }
}
```

</TabItem>
</Tabs>

السطر `if not swapped: break` تحسين مهم: إذا مرّت جولة كاملة دون تبديل، فالقائمة مرتبة، ولا داعي للباقي.

## الترتيب بالاختيار

نبحث عن **أصغر** عنصر في القائمة كلها، ونضعه في المكان الأول. ثم نبحث عن أصغر عنصر في الباقي، ونضعه في المكان الثاني. وهكذا. وهي غالباً الطريقة التي رتّبت بها الأوراق بيدك! وتُسمّى <Term t="الترتيب بالاختيار" en="Selection Sort" def="ترتيب يختار في كل جولة أصغر عنصر من الجزء غير المرتب، ويضعه في أوله بتبديل واحد." />.

<SortLab algo="selection" lock />

**ماذا يجب أن ترى؟** اللون البرتقالي «يمسح» كل الجزء غير المرتب ليجد الأصغر، ثم **تبديل واحد فقط** في آخر كل جولة. لذلك عدد التبديلات قليل جداً (5 مع المدخلات العشوائية). لكن المقارنات **28 دائماً**، حتى لو كانت القائمة مرتبة أصلاً!

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def selection_sort(a):
    n = len(a)
    for i in range(n - 1):
        m = i
        for j in range(i + 1, n):         # find the smallest in a[i:]
            if a[j] < a[m]:
                m = j
        a[i], a[m] = a[m], a[i]           # one swap per pass
    return a
```

</TabItem>
<TabItem label="C++">

```cpp
void selectionSort(vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n - 1; i++) {
        int m = i;
        for (int j = i + 1; j < n; j++)
            if (a[j] < a[m]) m = j;
        swap(a[i], a[m]);
    }
}
```

</TabItem>
</Tabs>

## الترتيب بالإدراج

مثل ترتيب أوراق اللعب وأنت تسحبها واحدة واحدة: تأخذ الورقة الجديدة، و**تُدخلها** في مكانها الصحيح بين الأوراق المرتبة في يدك، بأن تزيح الأكبر منها نحو اليمين. ويُسمّى <Term t="الترتيب بالإدراج" en="Insertion Sort" def="ترتيب يأخذ العناصر واحداً واحداً، ويُدخل كل عنصر في مكانه الصحيح بين العناصر المرتبة قبله." />.

<SortLab algo="insertion" lock />

**ماذا يجب أن ترى؟** الجزء الأخضر في اليسار يكبر عنصراً كل مرة. وكل عنصر جديد «يرجع» نحو اليسار حتى يجد مكانه. جرّب «شبه مرتب»: **8 مقارنات فقط**، لأن كل عنصر تقريباً في مكانه أصلاً.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def insertion_sort(a):
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:      # shift bigger items right
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key                    # drop the card in its place
    return a
```

</TabItem>
<TabItem label="C++">

```cpp
void insertionSort(vector<int>& a) {
    for (int i = 1; i < (int)a.size(); i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;
    }
}
```

</TabItem>
</Tabs>

<Aside type="note">
في الكود الحقيقي، الإدراج لا يبدّل في كل خطوة، بل **يزيح** العناصر الأكبر ثم يضع العنصر مرة واحدة، وهذا أسرع. وفي المختبر نعدّ كل إزاحة «تبديلاً» لتسهل المقارنة.
</Aside>

## قارن الثلاثة

<SortLab />

افتح «جدول المقارنة» تحت المختبر. هذه الأرقام من المحرك نفسه، لقائمة من 8 عناصر:

| المدخلات | الفقاعي | الاختيار | الإدراج |
| --- | --- | --- | --- |
| عشوائي | 25 مقارنة، 13 تبديلاً | 28 مقارنة، 5 تبديلات | 18 مقارنة، 13 تبديلاً |
| مرتب أصلاً | 7، 0 | 28، 0 | 7، 0 |
| معكوس | 28، 28 | 28، 4 | 28، 28 |
| شبه مرتب | 13، 1 | 28، 1 | 8، 1 |

**ثلاث ملاحظات مهمة:**

1. **الاختيار لا يتعلم:** 28 مقارنة في كل الحالات، لأنه يبحث عن الأصغر في كل الباقي دائماً، حتى لو كانت القائمة مرتبة.
2. **الاختيار يبدّل أقل:** على الأكثر $n - 1$ تبديل. مفيد عندما يكون التحريك مكلفاً.
3. **الإدراج يحب القوائم شبه المرتبة:** مع «شبه مرتب» 8 مقارنات فقط، أي تقريباً $n$.

## الانقلابات: سرّ رقم 13

لاحظ أن الفقاعي والإدراج قاما بـ **13** تبديلاً بالضبط مع القائمة العشوائية `[5, 2, 8, 1, 9, 3, 7, 4]`. هل هي صدفة؟ لا!

<Term t="الانقلاب" en="Inversion" def="زوج من العناصر في مكانين خاطئين بالنسبة لبعضهما: العنصر الأكبر قبل الأصغر. مثلاً في [3، 1، 2] انقلابان: (3، 1) و (3، 2)." /> هو كل زوج من العناصر يكون فيه الأكبر قبل الأصغر. في قائمتنا: 5 قبل 2 و 1 و 3 و 4 (أربعة)، و 2 قبل 1 (واحد)، و 8 قبل 1 و 3 و 7 و 4 (أربعة)، و 9 قبل 3 و 7 و 4 (ثلاثة)، و 7 قبل 4 (واحد). المجموع **13**.

وكل تبديل بين جارين في الفقاعي يصلح **انقلاباً واحداً بالضبط**، لا أكثر ولا أقل. لذلك:

> عدد تبديلات الفقاعي والإدراج = عدد الانقلابات في القائمة.

- القائمة المرتبة فيها 0 انقلابات.
- القائمة المعكوسة فيها أكبر عدد ممكن: $\frac{n(n-1)}{2}$، أي 28 لثمانية عناصر.
- وفي المتوسط، نصف هذا العدد. لذلك الفقاعي والإدراج $O(n^2)$ في المتوسط أيضاً.

## صفتان مهمتان

### الثبات

<Term t="الترتيب الثابت" en="Stable Sort" def="ترتيب يحافظ على الترتيب الأصلي للعناصر المتساوية. إذا كان سامي قبل ريم وعلامتهما متساوية، يبقى سامي قبل ريم بعد الترتيب." /> هو الذي **يحافظ على ترتيب العناصر المتساوية** كما كانت. مثال: قائمة طلاب مرتبة أبجدياً، ونريد ترتيبها حسب العلامة:

| قبل (أبجدياً) | بعد الترتيب الثابت حسب العلامة |
| --- | --- |
| أحمد 80 | سارة 70 |
| ريم 90 | أحمد 80 |
| سارة 70 | عمر 80 |
| عمر 80 | ريم 90 |

أحمد وعمر علامتهما 80. في الترتيب الثابت يبقى أحمد قبل عمر (أبجدياً). فنحصل على ترتيب حسب العلامة، و**داخل كل علامة أبجدياً**، مجاناً!

- **الفقاعي والإدراج ثابتان:** لا يبدّلان إلا إذا كان الأول **أكبر تماماً**.
- **الاختيار غير ثابت:** التبديل البعيد قد يقفز بعنصر فوق عنصر يساويه. مثلاً `[5أ, 5ب, 2]`: أول جولة تبدّل 5أ مع 2، فتصبح `[2, 5ب, 5أ]`.

### الترتيب في المكان

الخوارزميات الثلاث ترتّب <Term t="في المكان" en="In-place" def="ترتيب لا يحتاج إلا ذاكرة إضافية صغيرة ثابتة، فيرتّب العناصر داخل القائمة نفسها دون نسخها إلى قائمة أخرى." />: لا تحتاج إلا متغيرات قليلة، أي ذاكرة إضافية $O(1)$. وسترى في المستوى الثاني خوارزمية (الدمج) أسرع بكثير، لكنها تحتاج ذاكرة إضافية.

## الجدول الكامل

| | **الفقاعي** | **الاختيار** | **الإدراج** |
| --- | --- | --- | --- |
| أفضل حالة | $O(n)$ مع التحسين | $O(n^2)$ | $O(n)$ |
| الحالة المتوسطة | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| أسوأ حالة | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| أكثر عدد للتبديلات | $O(n^2)$ | $n - 1$ فقط | $O(n^2)$ |
| ذاكرة إضافية | $O(1)$ | $O(1)$ | $O(1)$ |
| ثابت؟ | نعم | لا | نعم |
| متى نستخدمه؟ | للتعليم فقط تقريباً | عندما يكون التحريك مكلفاً جداً | قوائم صغيرة أو شبه مرتبة |

<Aside type="caution" title="الإدراج يعمل في كل حاسوب">
الإدراج ليس مجرد مثال تعليمي. دوال الترتيب الجاهزة في Python (`sorted`) و C++ (`std::sort`) تستخدم الإدراج **داخلها** للأجزاء الصغيرة (أقل من 16 إلى 64 عنصراً تقريباً)، لأنه مع القوائم الصغيرة أسرع من الخوارزميات المعقدة. وخوارزمية Python اسمها <Term t="Timsort" en="Timsort" def="خوارزمية الترتيب التي تستخدمها Python و Java، تجمع بين الترتيب بالإدراج للأجزاء الصغيرة والترتيب بالدمج، وتستفيد كثيراً من الأجزاء المرتبة أصلاً." />.
</Aside>

## الخلاصة

- **الفقاعي**: يقارن الجيران ويبدّلهم، والأكبر يطفو إلى النهاية. مع التحسين يتوقف مبكراً إذا كانت القائمة مرتبة.
- **الاختيار**: يختار الأصغر ويضعه أولاً. مقارناته ثابتة $\frac{n(n-1)}{2}$، وتبديلاته قليلة جداً، لكنه غير ثابت.
- **الإدراج**: يُدخل كل عنصر في مكانه. ممتاز للقوائم الصغيرة وشبه المرتبة، وتستخدمه اللغات داخل دوالها.
- تبديلات الفقاعي والإدراج = **عدد الانقلابات**.
- الثلاثة $O(n^2)$ في المتوسط، و $O(1)$ ذاكرة إضافية.

</details>

<summary>لماذا أفضل حالة للإدراج O(n)، وأفضل حالة للاختيار O(n²)؟</summary>

في الإدراج، إذا كانت القائمة مرتبة، يقارن كل عنصر مع الذي قبله مرة واحدة فقط ويتوقف، أي n − 1 مقارنة. أما الاختيار فيبحث دائماً عن الأصغر في كل الباقي، ولا يعرف أنه في مكانه حتى يقارنه بكل العناصر.
</details>

<details class="answer">
<summary>أعط مثالاً يبيّن أن الترتيب بالاختيار غير ثابت.</summary>

[5أ، 5ب، 2]: في أول جولة الأصغر 2، فنبدّله مع 5أ ← [2، 5ب، 5أ]. أصبح 5ب قبل 5أ، مع أن 5أ كان قبله في الأصل.
</details>

<details class="answer">
<summary>ما علاقة الانقلابات بسرعة الترتيب بالإدراج؟</summary>

كل إزاحة في الإدراج تصلح انقلاباً واحداً. فإذا كانت الانقلابات قليلة (قائمة شبه مرتبة)، يكون الإدراج سريعاً جداً، وإذا كانت كثيرة (قائمة معكوسة) يكون بطيئاً. وزمنه $O(n + k)$ حيث k عدد الانقلابات.
</details>
