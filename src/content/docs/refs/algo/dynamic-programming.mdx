<Aside type="tip" title="الفكرة ببساطة">
اكتب على ورقة: 1 + 1 + 1 + 1 + 1 + 1 + 1 + 1. كم المجموع؟ ستعدّ: **ثمانية**. والآن أضف «+ 1» في آخرها. كم المجموع؟ **تسعة**، فوراً! لم تعدّ من جديد، لأنك **تذكرت** أن ما قبله ثمانية. هذه هي **البرمجة الديناميكية** كلها: احفظ أجوبة المسائل الصغيرة، وابنِ منها جواب المسألة الكبيرة، ولا تحسب الشيء نفسه مرتين.
</Aside>

## ماذا ستتعلم؟

- ما هي **البرمجة الديناميكية**، ومتى نستخدمها.
- الفرق بين **التذكّر** (من الأعلى) و**الجدول** (من الأسفل).
- **خمس خطوات** لتصميم أي حل بالبرمجة الديناميكية.
- ثلاث مسائل مشهورة خانة خانة: **الفكّة**، و**حقيبة الظهر**، و**أطول تسلسل مشترك**.
- الفرق بينها وبين **الطمع** و**فرّق تسد**.

## ما هي البرمجة الديناميكية؟

<Concept term="البرمجة الديناميكية" en="Dynamic Programming (DP)">

طريقة لحل المسائل التي تتكرر فيها **المسائل الجزئية نفسها** مرات كثيرة: نحل كل مسألة جزئية **مرة واحدة فقط**، ونحفظ جوابها في جدول، ثم نبني منها جواب المسألة الكبيرة. والاسم لا علاقة له بالبرمجة بمعنى كتابة الكود: كلمة «برمجة» هنا قديمة وتعني «جدولة» أو «تخطيط».

**لماذا نستخدمها؟** لأنها تحوّل حلولاً **أسّية** مستحيلة إلى حلول **كثيرة الحدود** سريعة. رأيت ذلك في [العودية](../recursion/): فيبوناتشي من 2,692,537 استدعاء إلى 59 فقط.

**أين تُستخدم؟** التدقيق الإملائي («هل تقصد...؟»)، ومقارنة الملفات في Git، ومطابقة سلاسل الحمض النووي في علم الأحياء، والتعرف على الكلام، وتخطيط مسار الروبوتات، والاقتصاد والاستثمار.

</Concept>

```python
from functools import lru_cache

# 1. top-down (memoization): the natural recursion + remember answers
@lru_cache(maxsize=None)
def fib_top(n):
    if n < 2:
        return n
    return fib_top(n - 1) + fib_top(n - 2)

# 2. bottom-up (tabulation): fill a table from the smallest case
def fib_bottom(n):
    table = [0, 1]
    for k in range(2, n + 1):
        table.append(table[k - 1] + table[k - 2])
    return table[n]

print(fib_top(50), fib_bottom(50))   # 12586269025 12586269025
```

</TabItem>

```cpp
// 1. top-down (memoization)
long long memo[100];
bool known[100];
long long fibTop(int n) {
    if (n < 2) return n;
    if (known[n]) return memo[n];
    known[n] = true;
    return memo[n] = fibTop(n - 1) + fibTop(n - 2);
}

// 2. bottom-up (tabulation)
long long fibBottom(int n) {
    vector<long long> t(max(2, n + 1));
    t[0] = 0; t[1] = 1;
    for (int k = 2; k <= n; k++) t[k] = t[k - 1] + t[k - 2];
    return t[n];
}
```

## خمس خطوات لأي مسألة

1. **عرّف الحالة:** ماذا يعني `dp[...]`؟ اكتبها بجملة واضحة. (مثلاً: «أقل عدد قطع لدفع المبلغ a»)
2. **العلاقة:** كيف نحسب الحالة من حالات أصغر؟ (فكّر في **القرار الأخير**: ما آخر قطعة دفعناها؟)
3. **الحالات الأساسية:** ما أصغر حالة نعرف جوابها مباشرة؟
4. **ترتيب الحساب:** بأي ترتيب نملأ الجدول حتى تكون الحالات الأصغر جاهزة دائماً؟
5. **الجواب:** أي خانة فيها الجواب؟ وكيف **نرجع** لنعرف الاختيارات نفسها، لا الرقم فقط؟

## المسألة الأولى: الفكّة الصحيحة

في [الصفحة السابقة](../greedy/) فشل الطمع مع القطع 1، 3، 4 والمبلغ 6. الآن نطبّق الخطوات الخمس:

1. `dp[a]` = أقل عدد قطع لدفع المبلغ a.
2. القرار الأخير: آخر قطعة c. فـ $dp[a] = 1 + \min_c \, dp[a - c]$.
3. $dp[0] = 0$.
4. نملأ من 0 صعوداً.
5. الجواب `dp[المبلغ]`، ونرجع بالقطعة الأخيرة المحفوظة.

<CoinDpLab />

**ماذا يجب أن ترى؟** عند المبلغ **6**: ثلاثة خيارات: آخر قطعة 1 (فيبقى 5 بقطعتين: المجموع 3)، أو 3 (فيبقى 3 بقطعة واحدة: المجموع **2**)، أو 4 (فيبقى 2 بقطعتين: المجموع 3). الأقل **2**، أي 3 + 3. والجدول لا يُخدع، لأنه يجرّب **كل** القرارات الأخيرة، لا الأكبر فقط.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def min_coins(amount, coins):
    INF = float("inf")
    dp = [0] + [INF] * amount            # dp[a] = fewest coins for a
    last = [0] * (amount + 1)
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
                last[a] = c
    out = []                             # walk back to list the coins
    while amount > 0 and dp[amount] < INF:
        out.append(last[amount])
        amount -= last[amount]
    return out

print(min_coins(6, [1, 3, 4]))           # [3, 3]
```

</TabItem>
<TabItem label="C++">

```cpp
int minCoins(int amount, const vector<int>& coins) {
    const int INF = 1e9;
    vector<int> dp(amount + 1, INF);
    dp[0] = 0;
    for (int a = 1; a <= amount; a++)
        for (int c : coins)
            if (c <= a && dp[a - c] + 1 < dp[a])
                dp[a] = dp[a - c] + 1;
    return dp[amount] >= INF ? -1 : dp[amount];
}
// minCoins(6, {1, 3, 4}) == 2
```

## المسألة الثانية: حقيبة الرحلة

حقيبة تحمل 10 كيلو، وأربعة أغراض لكل منها وزن و«أهمية». كل غرض إما أن تأخذه كله أو تتركه. هذه <Term t="حقيبة الظهر 0/1" en="0/1 Knapsack" def="مسألة اختيار أغراض لكل منها وزن وقيمة، لتحقق أكبر قيمة دون تجاوز سعة الحقيبة، مع أخذ الغرض كله أو تركه." />، وهي من أشهر مسائل البرمجة الديناميكية.

<KnapsackLab />

**ماذا يجب أن ترى؟**

1. **جرّب بيدك أولاً:** الطريقة الجشعة (الأعلى أهمية لكل كيلو) تأخذ الخيمة والماء: 9 كيلو و **44** نقطة، ويضيع الكيلو الأخير.
2. **املأ الجدول:** في كل خانة قراران: لا تأخذ الغرض (الخانة فوقها)، أو خذه (أهميته + أفضل قيمة للسعة الباقية). الخانتان اللتان نقارن بينهما بالبرتقالي.
3. **النتيجة: 46**، بالخيمة والطعام (10 كيلو تماماً). والأخضر طريق الرجوع.

العلاقة:

$$
T[i][w] = \max\big(T[i-1][w],\; v_i + T[i-1][w - w_i]\big)
$$

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def knapsack(items, W):                  # items: list of (weight, value)
    n = len(items)
    T = [[0] * (W + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        wi, vi = items[i - 1]
        for w in range(W + 1):
            T[i][w] = T[i - 1][w]                         # skip item i
            if wi <= w:
                T[i][w] = max(T[i][w], vi + T[i - 1][w - wi])   # take it
    chosen, w = [], W                    # walk back
    for i in range(n, 0, -1):
        if T[i][w] != T[i - 1][w]:
            chosen.append(i - 1)
            w -= items[i - 1][0]
    return T[n][W], chosen[::-1]

print(knapsack([(6, 30), (3, 14), (4, 16), (2, 9)], 10))   # (46, [0, 2])
```

</TabItem>
<TabItem label="C++">

```cpp
int knapsack(const vector<pair<int,int>>& items, int W) {   // (weight, value)
    vector<int> dp(W + 1, 0);            // one row is enough
    for (auto [wi, vi] : items)
        for (int w = W; w >= wi; w--)    // backwards: each item used once
            dp[w] = max(dp[w], vi + dp[w - wi]);
    return dp[W];
}
// knapsack({{6,30},{3,14},{4,16},{2,9}}, 10) == 46
```

</TabItem>
</Tabs>

لاحظ في C++ حيلة **توفير الذاكرة**: سطر واحد يكفي، بشرط أن نمشي من الكبير إلى الصغير، حتى لا نستخدم الغرض نفسه مرتين. الزمن $O(n \times W)$.

<Aside type="caution" title="سريع... بشرط">
$O(n \times W)$ يبدو سريعاً، لكن W هنا **قيمة** السعة، لا عدد عناصر. فإذا كانت السعة مليار، يصبح الجدول مليار خانة. لذلك تُعد حقيبة الظهر مسألة «صعبة» في الحالة العامة، كما سترى في الصفحة 19.
</Aside>

## المسألة الثالثة: أطول تسلسل مشترك

ما أطول سلسلة حروف تظهر **بالترتيب نفسه** في كلمتين (ليس بالضرورة متجاورة)؟ هذا <Term t="أطول تسلسل مشترك" en="Longest Common Subsequence (LCS)" def="أطول سلسلة عناصر تظهر بالترتيب نفسه في سلسلتين، دون أن تكون متجاورة بالضرورة. تُستخدم في مقارنة الملفات والحمض النووي." />:

<LcsLab />

**ماذا يجب أن ترى؟** بين ALGORITHM و LOGARITHM: أطول تسلسل مشترك **LGRITHM**، طوله 7. جرّب كلمات أخرى، مثل `ABCBDAB` و `BDCABA` (الجواب بطول 4).

العلاقة: إذا تطابق الحرفان الأخيران، فهما جزء من الجواب: $T[i][j] = T[i-1][j-1] + 1$. وإلا نحذف أحدهما ونأخذ الأفضل: $T[i][j] = \max(T[i-1][j], T[i][j-1])$.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def lcs(a, b):
    T = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                T[i][j] = T[i - 1][j - 1] + 1
            else:
                T[i][j] = max(T[i - 1][j], T[i][j - 1])
    return T[len(a)][len(b)]

print(lcs("ALGORITHM", "LOGARITHM"))     # 7
```

</TabItem>
<TabItem label="C++">

```cpp
int lcs(const string& a, const string& b) {
    vector<vector<int>> T(a.size() + 1, vector<int>(b.size() + 1, 0));
    for (size_t i = 1; i <= a.size(); i++)
        for (size_t j = 1; j <= b.size(); j++)
            T[i][j] = a[i-1] == b[j-1] ? T[i-1][j-1] + 1
                                       : max(T[i-1][j], T[i][j-1]);
    return T[a.size()][b.size()];
}
```

هذه الفكرة نفسها في الأمر `diff` وفي Git: يحسب أطول تسلسل مشترك بين **أسطر** النسخة القديمة والجديدة من الملف، فما ليس في التسلسل المشترك هو الأسطر المحذوفة والمضافة. وقريبة منها <Term t="مسافة التحرير" en="Edit Distance" def="أقل عدد من عمليات الإضافة والحذف والاستبدال لتحويل كلمة إلى أخرى. تستخدمها برامج التدقيق الإملائي لاقتراح الكلمة الصحيحة." /> التي يستخدمها المدقق الإملائي ليقترح «هل تقصد...؟».

## مسائل مشهورة أخرى

| المسألة | الحالة | الزمن |
| --- | --- | --- |
| صعود درج بخطوة أو خطوتين: كم طريقة؟ | `dp[n] = dp[n-1] + dp[n-2]` (فيبوناتشي!) | $O(n)$ |
| أطول تسلسل متزايد | `dp[i]` = أطول تسلسل ينتهي عند i | $O(n^2)$ أو $O(n \log n)$ |
| مسافة التحرير | جدول مثل LCS بثلاث عمليات | $O(n \times m)$ |
| عدد الطرق في شبكة من الزاوية إلى الزاوية | `dp[i][j] = dp[i-1][j] + dp[i][j-1]` | $O(n \times m)$ |
| ضرب سلسلة مصفوفات بأقل كلفة | `dp[i][j]` أفضل ترتيب أقواس | $O(n^3)$ |

مثلاً، صعود درج من 10 درجات بخطوة أو خطوتين: **89** طريقة. وبالعودية البسيطة نحسبها بآلاف الاستدعاءات، وبالجدول بعشر خطوات.

## الخلاصة

- **البرمجة الديناميكية**: احفظ أجوبة المسائل الجزئية، ولا تحسب الشيء نفسه مرتين.
- تحتاج **بنية جزئية مثلى** و**مسائل جزئية متداخلة**.
- طريقتان: **التذكّر** من الأعلى، و**الجدول** من الأسفل.
- الخطوات: الحالة، والعلاقة (فكّر في القرار الأخير)، والحالات الأساسية، والترتيب، والجواب والرجوع.
- **الفكّة** تصلح فشل الطمع، و**حقيبة 0/1** $O(nW)$، و**أطول تسلسل مشترك** في `diff` و Git.

<details class="answer">
<summary>ما الفرق بين التذكّر والجدول؟ ومتى تفضّل كلاً منهما؟</summary>

التذكّر عودية مع حفظ، وتحسب فقط ما تحتاجه، وأسهل في الكتابة. والجدول يملأ كل الخانات من الأسفل، ولا يفيض المكدس، ويسهل فيه توفير الذاكرة. نفضّل التذكّر عندما يحتاج الحل جزءاً صغيراً من الحالات، والجدول عندما نحتاج كلها أو يكون العمق كبيراً.
</details>
