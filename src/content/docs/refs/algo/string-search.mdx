## ماذا ستتعلم؟

- **البحث البسيط** عن نمط في نص، ولماذا قد يكون بطيئاً جداً.
- خوارزمية **KMP**: لماذا لا ترجع في النص أبداً، وكيف تعمل بجدول الإزاحة.
- فكرة **Rabin-Karp**: نقارن **بصمات** بدل الحروف.
- **Boyer-Moore**: البحث من آخر النمط، وما تستخدمه البرامج فعلاً.
- **شجرة البادئات** للإكمال التلقائي.

## المسألة

<Concept term="مطابقة النصوص" en="String Matching">

إيجاد كل المواقع التي يظهر فيها **نمط** قصير (كلمة) داخل **نص** طويل. نرمز لطول النص بـ n، ولطول النمط بـ m.

**لماذا نحتاجها؟** لأنها من أكثر العمليات تكراراً في الحاسوب: البحث في المستندات، والاستبدال في المحررات، وتصفية الرسائل المزعجة، وأدوات البرمجة.

**أين تُستخدم؟** Ctrl + F في كل برنامج، ومحركات البحث، وكشف الانتحال، وكشف الفيروسات (البحث عن «بصمة» الفيروس داخل الملفات)، وعلم الأحياء: البحث عن تسلسل جيني (مثل GATTACA) داخل حمض نووي فيه مليارات الحروف.

</Concept>

## جرّب الطريقتين

<StringLab />

**ماذا يجب أن ترى؟**

1. **البسيط، النمط الأول:** عند كل اختلاف يرجع النمط إلى أوله وينزاح خانة واحدة، فيعيد مقارنة حروف طابقها للتو. المجموع **29** مقارنة.
2. **KMP، النمط نفسه:** عند الاختلاف، يقفز النمط بحسب «جدول الإزاحة»، والمربع البرتقالي في النص **لا يرجع إلى الخلف أبداً**. المجموع **23** مقارنة.
3. **النمط AAAAB:** هذه أسوأ حالة للبسيط: في كل إزاحة يطابق 4 حروف ثم يفشل في الخامس. **80** مقارنة مقابل **35** لـ KMP.

## البحث البسيط

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def naive_search(text, pat):
    n, m = len(text), len(pat)
    found = []
    for s in range(n - m + 1):          # every shift
        j = 0
        while j < m and text[s + j] == pat[j]:
            j += 1
        if j == m:
            found.append(s)
    return found

print(naive_search("THE CAT SAT ON THE MAT", "THE"))   # [0, 15]
```

</TabItem>
<TabItem label="C++">

```cpp
vector<int> naiveSearch(const string& text, const string& pat) {
    int n = text.size(), m = pat.size();
    vector<int> found;
    for (int s = 0; s + m <= n; s++) {
        int j = 0;
        while (j < m && text[s + j] == pat[j]) j++;
        if (j == m) found.push_back(s);
    }
    return found;
}
```

</TabItem>

في أسوأ حالة يقارن m حرفاً في كل واحدة من قرابة n إزاحة، أي $O(n \times m)$. ومع نص فيه مليون حرف ونمط فيه ألف حرف، هذا مليار مقارنة. لكن **مع النصوص العادية** (لغة بشرية) يفشل غالباً من الحرف الأول، فيكون سريعاً عملياً.

## خوارزمية KMP

نشرها <Term t="Knuth و Morris و Pratt" en="Knuth–Morris–Pratt" def="ثلاثة علماء نشروا عام 1977 خوارزمية البحث في النصوص التي تحمل الحروف الأولى من أسمائهم: KMP." /> عام 1977، وفكرتها: **عندما نفشل بعد أن طابقنا جزءاً، نحن نعرف هذا الجزء!** فلماذا نعيد مقارنته؟

مثال: النمط `ABABC`، وطابقنا `ABAB` ثم فشلنا. آخر حرفين طابقناهما `AB` هما أيضاً **بداية** النمط. إذن نستطيع أن نزيح النمط ليبدأ عندهما، ونكمل المقارنة من الحرف الثالث، دون أن نرجع في النص.

### جدول الإزاحة

لكل موقع في النمط، نحسب **طول أطول بادئة هي أيضاً لاحقة** للجزء حتى هذا الموقع. وهذا <Term t="جدول الإزاحة" en="Failure Function / LPS Table" def="جدول لكل موقع في النمط، يحفظ طول أطول جزء في بداية النمط يساوي جزءاً في نهاية ما طابقناه حتى الآن، فنعرف كم نزيح النمط عند الفشل." />:

| النمط حتى هنا | أطول بادئة = لاحقة | القيمة |
| --- | --- | --- |
| `A` | لا شيء | 0 |
| `AB` | لا شيء | 0 |
| `ABA` | `A` | 1 |
| `ABAB` | `AB` | 2 |
| `ABABC` | لا شيء | 0 |

ونحسب الجدول مرة واحدة قبل البحث، بزمن $O(m)$. ثم البحث نفسه $O(n)$، لأن مؤشر النص يتقدم فقط. فالمجموع $O(n + m)$، **مهما كانت المدخلات**.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def lps_table(pat):
    lps, k = [0] * len(pat), 0
    for i in range(1, len(pat)):
        while k > 0 and pat[i] != pat[k]:
            k = lps[k - 1]               # fall back to a shorter border
        if pat[i] == pat[k]:
            k += 1
        lps[i] = k
    return lps

def kmp_search(text, pat):
    lps, j, found = lps_table(pat), 0, []
    for i, c in enumerate(text):         # i never goes back
        while j > 0 and c != pat[j]:
            j = lps[j - 1]               # shift the pattern, not the text
        if c == pat[j]:
            j += 1
        if j == len(pat):
            found.append(i - j + 1)
            j = lps[j - 1]
    return found

print(lps_table("ABABCABAB"))                              # [0, 0, 1, 2, 0, 1, 2, 3, 4]
print(kmp_search("ABABDABACDABABCABAB", "ABABCABAB"))      # [10]
```

</TabItem>
<TabItem label="C++">

```cpp
vector<int> lpsTable(const string& p) {
    vector<int> lps(p.size(), 0);
    for (size_t i = 1, k = 0; i < p.size(); i++) {
        while (k > 0 && p[i] != p[k]) k = lps[k - 1];
        if (p[i] == p[k]) k++;
        lps[i] = k;
    }
    return lps;
}

vector<int> kmpSearch(const string& t, const string& p) {
    vector<int> lps = lpsTable(p), found;
    size_t j = 0;
    for (size_t i = 0; i < t.size(); i++) {
        while (j > 0 && t[i] != p[j]) j = lps[j - 1];
        if (t[i] == p[j]) j++;
        if (j == p.size()) { found.push_back(i - j + 1); j = lps[j - 1]; }
    }
    return found;
}
```

## Rabin-Karp: قارن البصمات

فكرة مختلفة تماماً: بدل أن نقارن الحروف، نحسب لكل نافذة بطول m في النص **بصمة** (عدداً) بدالة تجزئة، كما في [جداول التجزئة](../hashing/)، ونقارنها ببصمة النمط. فإذا تساوت البصمتان، نتأكد حرفاً حرفاً (لأن التصادم ممكن).

والحيلة الذكية: <Term t="التجزئة المتدحرجة" en="Rolling Hash" def="طريقة لحساب بصمة النافذة التالية من بصمة النافذة الحالية بعمليات قليلة: نطرح أثر الحرف الخارج ونضيف أثر الحرف الداخل، بدل حساب البصمة من جديد." />: عندما تنزاح النافذة خانة، لا نحسب البصمة من جديد، بل **نطرح** أثر الحرف الذي خرج و**نضيف** أثر الحرف الذي دخل، بعمليات قليلة ثابتة. فيكون البحث $O(n + m)$ في المتوسط.

وقوة Rabin-Karp أنها تبحث عن **أنماط كثيرة معاً**: نحسب بصمات آلاف الجمل، ثم نمرّ على النص مرة واحدة. وهكذا تعمل برامج **كشف الانتحال**: تقسم البحث إلى جمل قصيرة، وتبحث عن بصماتها في ملايين الأبحاث.

## Boyer-Moore: ابدأ من الآخر

خوارزمية <Term t="Boyer-Moore" en="Boyer–Moore Algorithm" def="خوارزمية بحث في النصوص تقارن النمط من آخره، وعند الفشل تقفز قفزات كبيرة اعتماداً على الحرف الذي لم يطابق. سريعة جداً مع النصوص العادية." /> تقارن النمط **من آخره**. فإذا كان حرف النص المقابل لآخر النمط غير موجود في النمط أصلاً، تقفز بالنمط **كله** إلى ما بعده! مع النصوص العادية والأنماط الطويلة، تقفز غالباً قفزات كبيرة، فتقرأ جزءاً صغيراً فقط من النص. ولذلك تستخدم أداة البحث `grep` في لينكس أفكاراً منها.

## شجرة البادئات

عندما تكتب «خوا» في محرك البحث، يقترح عليك «خوارزمية» و«خوارزميات». كيف يجد كل الكلمات التي تبدأ بما كتبت بسرعة؟ ببنية اسمها <Term t="شجرة البادئات" en="Trie" def="شجرة كل عقدة فيها حرف، وكل طريق من الجذر يكوّن كلمة. كل الكلمات التي تبدأ بالبادئة نفسها تشترك في الطريق نفسه، فالإكمال التلقائي سريع جداً." />: كل عقدة حرف، وكل طريق من الجذر يكوّن كلمة. والكلمات التي تبدأ بالحروف نفسها **تشترك في الطريق نفسه**. فإيجاد كل الكلمات التي تبدأ بـ«خوا» يحتاج 3 خطوات للوصول، ثم نقرأ ما تحت العقدة. وتُستخدم في الإكمال التلقائي، والتدقيق الإملائي، وتوجيه الرسائل في الإنترنت.

## المقارنة

| الخوارزمية | التحضير | البحث | ميزتها |
| --- | --- | --- | --- |
| البسيطة | لا شيء | $O(nm)$ أسوأ حالة | الأبسط، وسريعة مع النصوص العادية |
| **KMP** | $O(m)$ | $O(n)$ مضمون | لا ترجع في النص، فتصلح للبيانات المتدفقة |
| **Rabin-Karp** | $O(m)$ | $O(n)$ متوسط | أنماط كثيرة معاً |
| **Boyer-Moore** | $O(m + \sigma)$ | غالباً أقل من n | الأسرع عملياً مع الأنماط الطويلة |

حيث σ عدد الحروف المختلفة في الأبجدية.

<Aside type="note" title="في الواقع">
`"cat" in text` في Python و `text.find("cat")` في C++ تستخدم خوارزميات محسّنة مكتوبة بلغة الآلة، تجمع أفكاراً من هذه الطرق. فاستخدمها في عملك، واكتب KMP بنفسك فقط لتفهم الفكرة، أو في مسابقة تحتاج ضماناً $O(n + m)$.
</Aside>

## الخلاصة

- **البسيط** $O(nm)$ في أسوأ حالة: يعيد مقارنة ما طابقه.
- **KMP** $O(n + m)$: جدول الإزاحة يخبرنا كم نزيح النمط، ولا نرجع في النص أبداً.
- **Rabin-Karp**: بصمات متدحرجة، ممتازة لأنماط كثيرة معاً وكشف الانتحال.
- **Boyer-Moore**: يقارن من الآخر ويقفز قفزات كبيرة، وهو الأسرع عملياً غالباً.
- **شجرة البادئات** للإكمال التلقائي.

## أسئلة المراجعة

<details class="answer">
<summary>كم مقارنة يحتاج البحث البسيط عن AAB في النص AAAAAA؟</summary>

النمط يمكن أن يبدأ في 4 مواقع (0 إلى 3). في كل موقع يطابق AA ثم يفشل في B، أي 3 مقارنات. المجموع 4 × 3 = 12، ولا يجد شيئاً.
</details>

<details class="answer">
<summary>احسب جدول الإزاحة للنمط ABCAB.</summary>

A: 0، و AB: 0، و ABC: 0، و ABCA: 1 (البادئة A = اللاحقة A)، و ABCAB: 2 (AB). فالجدول 0 0 0 1 2.
</details>

<details class="answer">
<summary>لماذا يتحقق Rabin-Karp حرفاً حرفاً عندما تتساوى البصمتان؟</summary>

لأن دالة التجزئة قد تعطي البصمة نفسها لنصين مختلفين (تصادم). فتساوي البصمتين يعني «ربما»، وتساويهما حرفاً حرفاً يعني «نعم بالتأكيد».
</details>

<details class="answer">
<summary>متى يكون البحث البسيط كافياً عملياً؟</summary>

مع النصوص البشرية العادية والأنماط القصيرة، لأن الاختلاف يظهر غالباً من الحرف الأول، فتكون كل إزاحة مقارنة واحدة تقريباً. أسوأ حالته تظهر مع نصوص متكررة جداً مثل AAAA...AB.
</details>
