<Aside type="tip" title="الفكرة ببساطة">
أنت في طابور طويل، وتريد أن تعرف رقمك. لا ترى أول الطابور. فتسأل الشخص الذي أمامك: «ما رقمك؟». وهو لا يعرف أيضاً، فيسأل الذي أمامه... حتى يصل السؤال إلى **أول** شخص، فيقول: «أنا رقم 1». ثم يرجع الجواب: «إذن أنا 2»، «إذن أنا 3»... حتى يصلك. هذه هي **العودية**: مسألة كبيرة تُحل بسؤال **نسخة أصغر منها**، حتى نصل إلى نسخة صغيرة نعرف جوابها مباشرة.
</Aside>

## ماذا ستتعلم؟

- ما هي العودية، وجزآها: **الحالة الأساسية** و**الحالة العودية**.
- كيف يعمل **مكدس الاستدعاءات**، ولماذا قد «يفيض».
- لماذا قد تكون العودية **بطيئة جداً**، وكيف ينقذها **التذكّر**.
- كيف تحل لغزاً صعباً مثل **أبراج هانوي** بثلاثة أسطر.
- متى نستخدم العودية، ومتى الحلقة أفضل.
- كيف نحسب تعقيد الدالة العودية بـ**علاقة التكرار**.

## ما هي العودية؟

<Concept term="العودية" en="Recursion">

**أن تستدعي الدالة نفسها، لتحل نسخة أصغر من المسألة نفسها.** مثل الدمى الروسية: تفتح الدمية فتجد دمية أصغر، فتفتحها فتجد أصغر، حتى تصل إلى أصغر دمية لا تُفتح.

**لماذا نستخدمها؟** لأن مسائل كثيرة **مبنية من نسخ أصغر منها**: المجلد فيه مجلدات، والشجرة فيها أشجار أصغر، والقائمة هي عنصر وبعده قائمة أقصر. والعودية تجعل حل هذه المسائل قصيراً وواضحاً.

**أين تُستخدم؟** في البحث داخل المجلدات والملفات، وفي الأشجار وكل ما يشبهها (مثل صفحات الويب)، وفي خوارزميات «فرّق تسد» مثل الترتيب بالدمج والترتيب السريع، وفي حل الألغاز والألعاب.

</Concept>

كل دالة عودية صحيحة لها **جزآن**:

| الجزء | السؤال | في مثال الطابور |
| --- | --- | --- |
| **الحالة الأساسية** | متى نعرف الجواب مباشرة، دون استدعاء جديد؟ | أول شخص: «أنا رقم 1» |
| **الحالة العودية** | كيف نصغّر المسألة، ونستخدم جواب النسخة الأصغر؟ | «رقمي = رقم الذي أمامي + 1» |

بدون <Term t="الحالة الأساسية" en="Base Case" def="الحالة التي تعرف فيها الدالة العودية الجواب مباشرة دون أن تستدعي نفسها، فتتوقف السلسلة عندها." />، تستدعي الدالة نفسها إلى الأبد. وبدون أن تصغر المسألة في <Term t="الحالة العودية" en="Recursive Case" def="الجزء الذي تستدعي فيه الدالة نفسها على مسألة أصغر، ثم تستخدم الجواب لتبني جوابها." />، لن نصل إلى الحالة الأساسية أبداً.

## أول مثال: المضروب

المضروب $n! = n \times (n-1) \times \dots \times 2 \times 1$. فمثلاً $4! = 24$. ولاحظ أن:

$$
n! = n \times (n-1)! \qquad 1! = 1
$$

المضروب **معرّف بنفسه**! فكتابته بالعودية مباشرة:

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def fact(n):
    if n <= 1:                 # base case
        return 1
    return n * fact(n - 1)     # recursive case: a smaller problem

print(fact(4))  # 24
```

</TabItem>
<TabItem label="C++">

```cpp
long long fact(int n) {
    if (n <= 1) return 1;          // base case
    return n * fact(n - 1);        // recursive case
}
// fact(4) == 24
```

</TabItem>
</Tabs>

## مكدس الاستدعاءات

كيف «يتذكر» الحاسوب أن `fact(4)` ينتظر جواب `fact(3)`؟ يضع كل استدعاء في <Term t="مكدس الاستدعاءات" en="Call Stack" def="منطقة في الذاكرة يحفظ فيها الحاسوب كل دالة تعمل الآن ومتغيراتها والمكان الذي ستعود إليه. آخر دالة تدخل هي أول دالة تخرج، مثل الصحون فوق بعضها." />: مثل صحون فوق بعضها. كل استدعاء جديد صحن **فوق** المكدس، وعندما ينتهي يُرفع، فيكمل الصحن الذي تحته من حيث توقف.

<StackLab />

**ماذا يجب أن ترى؟**

1. **مرحلة النزول:** الصحون تتكدس: `fact(4)` ثم `fact(3)` ثم `fact(2)` ثم `fact(1)`. لا أحد يعرف جوابه بعد، والكل ينتظر.
2. **الحالة الأساسية:** `fact(1)` (بنفسجي) يعرف الجواب مباشرة: 1.
3. **مرحلة الرجوع:** الصحون تُرفع واحداً واحداً، وكل واحد يحسب جوابه من جواب الذي فوقه: 1، ثم 2، ثم 6، ثم 24.

### فيضان المكدس

المكدس له حجم محدود. فإذا نسيت الحالة الأساسية، أو كانت المسألة كبيرة جداً، تتراكم الصحون حتى يمتلئ المكدس، فيتوقف البرنامج بخطأ اسمه <Term t="فيضان المكدس" en="Stack Overflow" def="خطأ يحدث عندما تتراكم الاستدعاءات في مكدس الاستدعاءات حتى يمتلئ، غالباً بسبب عودية بلا حالة أساسية أو عميقة جداً." /> (ومنه جاء اسم الموقع المشهور للمبرمجين).

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def broken(n):
    return n * broken(n - 1)   # no base case!

broken(5)
# RecursionError: maximum recursion depth exceeded

import sys
print(sys.getrecursionlimit())  # 1000 by default
```

</TabItem>
<TabItem label="C++">

```cpp
int broken(int n) {
    return n * broken(n - 1);  // no base case!
}
// broken(5) -> the program crashes (stack overflow / segmentation fault)
```

</TabItem>
</Tabs>

في Python الحد الافتراضي 1000 استدعاء متداخل. لذلك `fact(5000)` بالعودية يفشل، أما بالحلقة فيعمل بسهولة.

## كيف تفكر بالعودية؟

السر هو **«قفزة الثقة»**: عندما تكتب `fact(n - 1)`، **لا تتبّعه في رأسك**. افترض فقط أنه يعيد الجواب الصحيح، واسأل: «إذا كان عندي جواب المسألة الأصغر، كيف أبني جواب مسألتي؟». ثلاثة أسئلة تكفي:

1. ما **أصغر** نسخة من المسألة، وما جوابها؟ (الحالة الأساسية)
2. كيف أجعل المسألة **أصغر** بخطوة واحدة؟
3. إذا عرفت جواب الأصغر، كيف أحصل على جوابي؟

جرّبها على ثلاثة أمثلة:

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
# 1. sum of digits: 4321 -> 4 + 3 + 2 + 1 = 10
def digit_sum(n):
    if n < 10:
        return n
    return n % 10 + digit_sum(n // 10)

# 2. palindrome: reads the same both ways
def is_palindrome(s):
    if len(s) <= 1:
        return True
    return s[0] == s[-1] and is_palindrome(s[1:-1])

# 3. power: x^n with only log n multiplications
def power(x, n):
    if n == 0:
        return 1
    half = power(x, n // 2)
    return half * half if n % 2 == 0 else half * half * x

print(digit_sum(4321), is_palindrome("level"), power(2, 10))  # 10 True 1024
```

</TabItem>
<TabItem label="C++">

```cpp
// 1. sum of digits
int digitSum(int n) {
    if (n < 10) return n;
    return n % 10 + digitSum(n / 10);
}

// 2. palindrome (check s[i..j])
bool isPalindrome(const string& s, int i, int j) {
    if (i >= j) return true;
    return s[i] == s[j] && isPalindrome(s, i + 1, j - 1);
}

// 3. power with log n multiplications
long long power(long long x, int n) {
    if (n == 0) return 1;
    long long half = power(x, n / 2);
    return n % 2 == 0 ? half * half : half * half * x;
}
```

</TabItem>
</Tabs>

لاحظ المثال الثالث: $2^{10}$ بالضرب العادي يحتاج 10 ضربات، أما هنا فيكفي حساب $2^5$ ثم تربيعه، و $2^5$ من $2^2$... فيحتاج قرابة $\log_2 10 \approx 4$ خطوات فقط. هذه فكرة <Term t="الرفع السريع" en="Fast Exponentiation" def="حساب x أس n بقسمة الأس على 2 في كل خطوة وتربيع النتيجة، فيحتاج قرابة log n ضربة بدل n." /> التي تُستخدم في كل خوارزميات التشفير.

## فيبوناتشي: عندما تنفجر العودية

متتالية فيبوناتشي: كل عدد هو مجموع العددين قبله: 0، 1، 1، 2، 3، 5، 8، 13، 21... وتعريفها عودي مباشرة:

$$
F(n) = F(n-1) + F(n-2) \qquad F(0) = 0,\; F(1) = 1
$$

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)   # two calls!
```

</TabItem>
<TabItem label="C++">

```cpp
long long fib(int n) {
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);   // two calls!
}
```

</TabItem>
</Tabs>

يبدو بسيطاً وجميلاً. لكن انظر ماذا يحدث فعلاً:

<FibTree />

**ماذا يجب أن ترى؟**

1. مع `fib(5)`: الدائرة الزرقاء (3) تظهر **مرتين**، والخضراء (2) **ثلاث مرات**. نحسب الشيء نفسه مرة بعد مرة! المجموع 15 استدعاء لحساب الرقم 5.
2. غيّر إلى 7: الشجرة تنفجر إلى 41 استدعاء. وكل زيادة في n تضرب العدد تقريباً في 1.6.
3. فعّل «مع التذكّر»: معظم الشجرة يبهت، ولا يبقى إلا خط واحد تقريباً.

لماذا؟ لأن كل استدعاء يولّد **استدعاءين**، فالعدد ينمو تقريباً مثل $1.6^n$. هذا تعقيد **أُسّي**: `fib(30)` يحتاج **2,692,537** استدعاء، و `fib(50)` يحتاج أكثر من **أربعين مليار**.

### التذكّر ينقذ الموقف

الحل: **احفظ كل جواب تحسبه**، وقبل أن تحسب أي شيء اسأل: «هل حسبته من قبل؟». وهذه الفكرة اسمها <Term t="التذكّر" en="Memoization" def="حفظ نتائج الاستدعاءات السابقة في جدول، فإذا تكرر الاستدعاء نفسه نعيد النتيجة المحفوظة فوراً بدل حسابها من جديد." />:

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
from functools import lru_cache

@lru_cache(maxsize=None)          # remembers every answer
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(100))  # 354224848179261915075, instantly
```

</TabItem>
<TabItem label="C++">

```cpp
#include <unordered_map>

unordered_map<int, long long> memo;

long long fib(int n) {
    if (n < 2) return n;
    if (memo.count(n)) return memo[n];          // already known
    return memo[n] = fib(n - 1) + fib(n - 2);   // compute once, save
}
```

</TabItem>
</Tabs>

مع التذكّر، `fib(30)` يحتاج **59** استدعاء فقط بدل 2,692,537. من $O(1.6^n)$ إلى $O(n)$، بسطرين! وهذه الفكرة هي أساس **البرمجة الديناميكية** التي ستراها في المستوى الرابع.

## أبراج هانوي

لغز قديم: ثلاثة أعمدة، وعلى الأول أقراص من الأكبر في الأسفل إلى الأصغر في الأعلى. انقلها كلها إلى العمود الثالث، قرصاً واحداً في كل مرة، ولا تضع قرصاً كبيراً فوق قرص أصغر. جرّب بنفسك أولاً:

<HanoiGame />

حاول مع 3 أقراص ثم 4. اللغز يبدو صعباً، لكن **التفكير العودي** يجعله سهلاً جداً. لنقل n قرصاً من A إلى C:

1. انقل أعلى $n-1$ قرصاً من A إلى B (مسألة أصغر من النوع نفسه!).
2. انقل القرص الأكبر من A إلى C (حركة واحدة).
3. انقل الـ $n-1$ قرصاً من B إلى C (مسألة أصغر مرة أخرى).

والحالة الأساسية: صفر أقراص، لا نفعل شيئاً.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def hanoi(n, a="A", c="C", b="B"):
    if n == 0:
        return
    hanoi(n - 1, a, b, c)          # move n-1 out of the way
    print(f"move disk {n}: {a} -> {c}")
    hanoi(n - 1, b, c, a)          # put them back on top

hanoi(3)   # 7 moves
```

</TabItem>
<TabItem label="C++">

```cpp
void hanoi(int n, char a = 'A', char c = 'C', char b = 'B') {
    if (n == 0) return;
    hanoi(n - 1, a, b, c);
    cout << "move disk " << n << ": " << a << " -> " << c << "\n";
    hanoi(n - 1, b, c, a);
}
// hanoi(3) prints 7 moves
```

</TabItem>
</Tabs>

**كم حركة؟** إذا كان $T(n)$ عدد الحركات لـ n قرصاً، فمن الخطوات الثلاث:

$$
T(n) = 2\,T(n-1) + 1 \qquad T(0) = 0
$$

وحلها $T(n) = 2^n - 1$: ‏3 أقراص 7 حركات، و 4 أقراص 15، و 5 أقراص 31، و 10 أقراص 1023. وتقول الأسطورة إن رهباناً ينقلون 64 قرصاً ذهبياً، وعندما ينتهون ينتهي العالم. بحركة كل ثانية، يحتاجون $2^{64} - 1$ ثانية: قرابة **584 مليار سنة**. فلا داعي للقلق!

## علاقات التكرار

المعادلة $T(n) = 2T(n-1) + 1$ اسمها <Term t="علاقة التكرار" en="Recurrence Relation" def="معادلة تصف زمن الدالة العودية بدلالة زمنها على مدخلات أصغر، مثل T(n) = T(n − 1) + 1." />، وهي الطريقة التي نحسب بها تعقيد الدوال العودية:

| الدالة | علاقة التكرار | الحل |
| --- | --- | --- |
| المضروب: استدعاء واحد أصغر بواحد | $T(n) = T(n-1) + 1$ | $O(n)$ |
| البحث الثنائي العودي: استدعاء واحد على النصف | $T(n) = T(n/2) + 1$ | $O(\log n)$ |
| الرفع السريع | $T(n) = T(n/2) + 1$ | $O(\log n)$ |
| الترتيب بالدمج: استدعاءان على النصفين، ثم دمج | $T(n) = 2T(n/2) + n$ | $O(n \log n)$ |
| هانوي: استدعاءان أصغر بواحد | $T(n) = 2T(n-1) + 1$ | $O(2^n)$ |
| فيبوناتشي البسيط | $T(n) = T(n-1) + T(n-2) + 1$ | $O(1.6^n)$ تقريباً |

**القاعدة العملية:** استدعاء واحد يصغّر المسألة **بطرح** ← خطي. استدعاء واحد **بالقسمة** ← لوغاريتمي. استدعاءان كل منهما يصغّر **بطرح** ← أُسّي (خطر!). استدعاءان **بالقسمة** مع عمل خطي ← $n \log n$.

## العودية أم الحلقة؟

كل دالة عودية يمكن كتابتها بحلقة (أحياناً مع مكدس نصنعه بأنفسنا)، والعكس صحيح. فمتى نختار ماذا؟

| | **العودية** | **الحلقة** |
| --- | --- | --- |
| الوضوح | أوضح للمسائل المتفرعة: الأشجار، والمجلدات، وفرّق تسد | أوضح للعدّ والتكرار البسيط |
| الذاكرة | كل استدعاء صحن في المكدس: $O(\text{depth})$ | غالباً $O(1)$ |
| السرعة | أبطأ قليلاً (كلفة كل استدعاء) | أسرع قليلاً |
| الخطر | فيضان المكدس مع العمق الكبير | لا يوجد |

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def fact_loop(n):
    result = 1
    for k in range(2, n + 1):
        result *= k
    return result

def fib_loop(n):           # O(n) time, O(1) memory
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

</TabItem>
<TabItem label="C++">

```cpp
long long factLoop(int n) {
    long long r = 1;
    for (int k = 2; k <= n; k++) r *= k;
    return r;
}

long long fibLoop(int n) {      // O(n) time, O(1) memory
    long long a = 0, b = 1;
    for (int i = 0; i < n; i++) { long long t = a + b; a = b; b = t; }
    return a;
}
```

</TabItem>
</Tabs>

</Aside>

## الخلاصة

- **العودية**: دالة تستدعي نفسها على نسخة أصغر من المسألة.
- لها **حالة أساسية** (نعرف جوابها مباشرة) و**حالة عودية** (تصغّر المسألة). بدون الأولى: استدعاء لا ينتهي.
- كل استدعاء **صحن في مكدس الاستدعاءات**، والعمق الكبير يسبب **فيضان المكدس**.
- فكّر بـ**قفزة الثقة**: افترض أن الاستدعاء الأصغر صحيح، واسأل كيف تبني جوابك منه.
- استدعاءان أصغر بواحد ← **انفجار أُسّي** (فيبوناتشي، هانوي). و**التذكّر** يحل التكرار.
- نحسب تعقيد العودية بـ**علاقة التكرار**، ونختار الحلقة عندما تكون أبسط أو عندما يكون العمق كبيراً.
