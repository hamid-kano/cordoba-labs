نسيت الرقم السري لقفل حقيبة من ثلاثة أرقام، لكنك تتذكر أن الرقم الأول فردي، وأن مجموع الأرقام 10. لن تجرّب الألف احتمال كلها! تبدأ بالرقم الأول 1، ثم تجرّب الثاني... فإذا تجاوز المجموع 10، **تتوقف عن هذا الطريق فوراً** وترجع خطوة. هذا هو **التراجع**: تجريب ذكي، يترك الطريق المسدود **مبكراً**، قبل أن يضيّع الوقت فيه.

## ماذا ستتعلم؟

- ما هو **التراجع**، وكيف يبني الحل خطوة خطوة ويرجع عند الطريق المسدود.
- **شجرة القرارات**، و**التقليم** الذي يجعل التراجع أسرع بكثير من التجريب الأعمى.
- **قالب** واحد يصلح لكل مسائل التراجع.
- ثلاث مسائل مشهورة: **الملكات**، و**السودوكو**، و**المجموعات الجزئية**.
- متى نستخدم التراجع، ومتى نبحث عن طريقة أسرع.

## ما هو التراجع؟

<Concept term="التراجع" en="Backtracking">

طريقة لحل المسائل التي نبني حلها **قراراً بعد قرار**: نأخذ قراراً، ثم ننتقل إلى القرار التالي. فإذا اكتشفنا أن الطريق لا يمكن أن يوصل إلى حل، **نرجع** عن آخر قرار ونجرّب غيره. مثل البحث بالعمق في متاهة: تمشي حتى الجدار، ثم ترجع إلى آخر مفترق.

**لماذا نستخدمه؟** لأن مسائل كثيرة ليس لها طريقة ذكية معروفة غير التجريب، لكن التجريب الأعمى مستحيل (مليارات الاحتمالات). والتراجع يقطع **أغصاناً كاملة** من الاحتمالات عند أول علامة فشل.

**أين يُستخدم؟** حل الألغاز (السودوكو، والكلمات المتقاطعة)، وجداول الامتحانات والمحاضرات، وتلوين الخرائط، ومحرّكات الشطرنج (مع تحسينات)، ولغات برمجة كاملة مثل <Term t="Prolog" en="Programming in Logic" def="لغة برمجة منطقية تعتمد على التراجع داخلياً: تكتب القواعد، وهي تجرّب وترجع حتى تجد جواباً." /> مبنية عليه.

</Concept>

## الملكات

اللغز المشهور: ضع n ملكات على رقعة n × n، بحيث لا تهاجم أي ملكة غيرها. والملكة تهاجم كل ما في سطرها، وعمودها، وقطريها. جرّب بيدك أولاً على 4 × 4:

<QueensLab />

**ماذا يجب أن ترى؟**

1. **أنا أحاول:** كل ملكة تضعها تلوّن بالأحمر كل الخانات التي تهاجمها. غالباً ستصل إلى صف كل خاناته حمراء: لا مخرج! يجب أن ترجع وتغيّر ملكة سابقة.
2. **التراجع خطوة خطوة:** الخوارزمية تضع ملكة في الصف الأول، ثم تبحث عن مكان آمن في الثاني... وعندما تعلق، ترفع آخر ملكة (برتقالي) وتجرّب العمود التالي.
3. على 4 × 4 تجد الحل بعد **8** ملكات وضعتها (ورفعت بعضها): الأعمدة 2، 4، 1، 3. ولو جرّبنا كل الترتيبات دون ذكاء، لاحتجنا $4^4 = 256$ محاولة.
4. جرّب 8 × 8 مع «الحل»: **113** ملكة فقط حتى أول حل، من بين $8^8$، أي قرابة 17 مليون ترتيب ممكن! وللرقعة 8 × 8 **92** حلاً مختلفاً.

## شجرة القرارات والتقليم

كل مسألة تراجع لها <Term t="شجرة القرارات" en="Decision Tree / State-Space Tree" def="شجرة يمثل كل مستوى فيها قراراً، وكل فرع اختياراً، وكل ورقة حلاً كاملاً أو طريقاً مسدوداً. التراجع يمشي فيها بالعمق." />: الجذر هو البداية الفارغة، وكل مستوى قرار (أين ملكة الصف الأول؟ ثم الثاني؟...)، وكل ورقة ترتيب كامل.

- **التجريب الأعمى** يزور **كل** الأوراق، ثم يفحص كل واحدة: هل هي حل؟
- **التراجع** يفحص بعد **كل** قرار: هل ما زال الحل ممكناً؟ فإذا كان الجواب لا، **يقطع** الغصن كله دون أن يزور ما تحته. وهذا القطع اسمه <Term t="التقليم" en="Pruning" def="ترك غصن كامل من شجرة القرارات دون زيارته، لأننا عرفنا مبكراً أنه لا يمكن أن يحتوي حلاً." />.

في الملكات: إذا تهاجمت ملكتا الصفين الأول والثاني، نقطع **كل** الترتيبات التي تبدأ بهما، دون أن نضع أي ملكة في الصفوف الباقية.

## القالب

كل مسائل التراجع تقريباً تُكتب بالقالب نفسه:

```text
SOLVE(state):
    if state is a complete solution:
        record it (or stop)
        return
    for each choice available now:
        if choice is valid:          // pruning
            make the choice
            SOLVE(next state)
            undo the choice          // backtrack
```

السطر الأهم هو الأخير: **ألغِ القرار**. لأننا نستخدم الحالة نفسها لكل الفروع، فيجب أن نعيدها كما كانت قبل أن نجرّب الخيار التالي.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def n_queens(n):
    cols = []                                   # cols[r] = column of the queen in row r
    solutions = []

    def safe(r, c):
        return all(cc != c and abs(cc - c) != r - rr for rr, cc in enumerate(cols))

    def place(r):
        if r == n:
            solutions.append(cols.copy())       # complete solution
            return
        for c in range(n):
            if safe(r, c):                      # prune
                cols.append(c)                  # choose
                place(r + 1)
                cols.pop()                      # undo

    place(0)
    return solutions

print(len(n_queens(8)))                         # 92
```

</TabItem>
<TabItem label="C++">

```cpp
int n, count = 0;
vector<int> cols;

bool safe(int r, int c) {
    for (int rr = 0; rr < r; rr++)
        if (cols[rr] == c || abs(cols[rr] - c) == r - rr) return false;
    return true;
}

void place(int r) {
    if (r == n) { count++; return; }
    for (int c = 0; c < n; c++)
        if (safe(r, c)) {
            cols.push_back(c);      // choose
            place(r + 1);
            cols.pop_back();        // undo
        }
}
// n = 8; place(0); -> count == 92
```

</TabItem>

## السودوكو

السودوكو مسألة تراجع مثالية: الخانات الفارغة هي القرارات، والأرقام 1 إلى 4 (أو 9) هي الخيارات، والقواعد هي التقليم:

<SudokuLab />

**ماذا يجب أن ترى؟** يملأ البرنامج الخانات بأصغر رقم مسموح. وفي السطر الثالث يعلق: خانة لا يصلح فيها أي رقم! فيمسح (أحمر) ويرجع ليجرّب رقماً أكبر في خانة سابقة. المجموع **5 تراجعات** حتى الحل.

<Aside type="note" title="التراجع الأذكى">
بدل أن نملأ الخانات بالترتيب، نختار في كل خطوة **الخانة التي فيها أقل عدد من الخيارات المسموحة**. فإذا كان لخانة خيار واحد فقط، نكتبه فوراً. وإذا كان لخانة صفر خيارات، نتراجع فوراً. هذه الحيلة البسيطة تجعل حل السودوكو 9 × 9 أسرع بآلاف المرات.
</Aside>

## المجموعات الجزئية والتباديل

كثير من مسائل التراجع هي اختيار **مجموعة** أو **ترتيب**:

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def subsets_with_sum(nums, target):
    out = []
    def go(k, chosen, total):
        if total == target:
            out.append(chosen.copy())
            return
        if k == len(nums) or total > target:   # prune: too big already
            return
        chosen.append(nums[k])                 # take nums[k]
        go(k + 1, chosen, total + nums[k])
        chosen.pop()                           # undo
        go(k + 1, chosen, total)               # skip nums[k]
    go(0, [], 0)
    return out

print(subsets_with_sum([3, 5, 6, 7, 2], 10))   # [[3, 5, 2], [3, 7]]

def permutations(items):
    out, cur, used = [], [], [False] * len(items)
    def go():
        if len(cur) == len(items):
            out.append(cur.copy())
            return
        for i, x in enumerate(items):
            if not used[i]:
                used[i] = True; cur.append(x)
                go()
                cur.pop(); used[i] = False   # undo
    go()
    return out

print(len(permutations("ABCD")))             # 24 = 4!
```

</TabItem>

```cpp
vector<int> nums = {3, 5, 6, 7, 2}, chosen;
int target = 10;

void go(int k, int total) {
    if (total == target) {
        for (int x : chosen) cout << x << " ";
        cout << "\n";
        return;
    }
    if (k == (int)nums.size() || total > target) return;   // prune
    chosen.push_back(nums[k]);
    go(k + 1, total + nums[k]);       // take
    chosen.pop_back();                // undo
    go(k + 1, total);                 // skip
}
// go(0, 0) prints: 3 5 2  and  3 7
```

لكل عنصر قراران: خذه أو اتركه، فشجرة المجموعات الجزئية فيها $2^n$ ورقة. والتقليم (`total > target`) يقطع الأغصان التي تجاوزت الهدف. ومع 5 أعداد، احتاج البحث **41** استدعاء ليجد الحلّين.

## التعقيد: لماذا ما زال بطيئاً؟

التراجع أسرع بكثير من التجريب الأعمى، لكن **أسوأ حالته ما زالت أسّية** غالباً: $O(2^n)$ للمجموعات الجزئية، و $O(n!)$ للتباديل والملكات. التقليم يقطع أغصاناً كثيرة عملياً، لكنه لا يغيّر الصنف في أسوأ حالة.

| المسألة | عدد الاحتمالات دون تقليم | مع n = 20 |
| --- | --- | --- |
| المجموعات الجزئية | $2^n$ | قرابة مليون |
| التباديل | $n!$ | $2.4 \times 10^{18}$ |
| الملكات (عمود لكل صف) | $n^n$ | $10^{26}$ |

لذلك نستخدم التراجع عندما يكون n **صغيراً** (حتى 20 أو 30 تقريباً حسب التقليم)، أو عندما لا توجد طريقة أفضل. وإذا كانت المسائل الجزئية **تتكرر**، فقد تنقذنا [البرمجة الديناميكية](../dynamic-programming/). وهناك تحسين اسمه <Term t="التفرع والتحديد" en="Branch and Bound" def="تحسين للتراجع في مسائل الأمثلية: يحسب لكل غصن حداً لأفضل نتيجة ممكنة فيه، فإذا كان أسوأ من أفضل حل وجدناه حتى الآن، يقطعه." /> لمسائل «أفضل حل»: إذا عرفنا أن أفضل ما يمكن في غصن ما أسوأ من حل وجدناه أصلاً، نقطعه.

## الخلاصة

- **التراجع**: ابنِ الحل قراراً بعد قرار، وارجع عن آخر قرار عند الطريق المسدود.
- يمشي في **شجرة القرارات** بالعمق، و**التقليم** يقطع الأغصان المستحيلة مبكراً.
- **القالب**: إذا اكتمل الحل سجّله، وإلا لكل خيار صالح: اختر، ثم استدعِ، ثم **ألغِ**.
- أمثلة: **الملكات** (92 حلاً لـ 8 × 8)، و**السودوكو**، و**المجموعات الجزئية**، و**التباديل**.
- أسوأ حالة غالباً **أسّية**، لذلك يناسب المدخلات الصغيرة، ويتحسن بالتقليم الذكي و**التفرع والتحديد**.

<details class="answer">
<summary>لماذا نلغي القرار بعد الاستدعاء العودي؟</summary>

لأننا نستخدم الحالة نفسها (مثل قائمة الملكات أو الخانات) لكل الفروع. فبعد أن ننتهي من فرع، يجب أن نعيد الحالة كما كانت قبله، حتى يبدأ الفرع التالي من البداية الصحيحة.
</details>

<details class="answer">
<summary>كيف تلوّن خريطة بثلاثة ألوان بحيث لا تتشابه منطقتان متجاورتان؟</summary>

بالتراجع: نمرّ على المناطق بالترتيب، ونعطي كل منطقة أول لون لا يستخدمه أي جار ملوّن. فإذا لم يبقَ لون مسموح، نرجع إلى المنطقة السابقة ونغيّر لونها. والتقليم: لا نعطي لوناً يستخدمه جار.
