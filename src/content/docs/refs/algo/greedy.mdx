في بوفيه مفتوح، طبقك صغير. ماذا تفعل؟ أغلب الناس يأخذون **أشهى** شيء أمامهم، ثم الأشهى من الباقي. هذه طريقة **جشعة**: في كل لحظة، خذ ما يبدو الأفضل **الآن**، ولا تفكر في المستقبل، ولا ترجع عن قرارك. أحياناً تعطيك أفضل طبق ممكن، وأحياناً تملأ الطبق بالمعكرونة فلا يبقى مكان للحلوى!

## ماذا ستتعلم؟

- ما هي **الخوارزمية الجشعة**، ولماذا هي جذابة جداً.
- متى **ينجح** الطمع، ومتى **يخدعك**، مع أمثلة تفشل فيها.
- **جدولة الأنشطة**: لماذا «ينتهي أولاً» هي القاعدة الصحيحة.
- **حجة التبديل**: كيف نثبت أن خوارزمية جشعة صحيحة.
- حقيبة الظهر **الكسرية**، وترميز **هوفمان**.

## ما هي الخوارزمية الجشعة؟

<Concept term="الخوارزمية الجشعة" en="Greedy Algorithm">

خوارزمية تبني الحل **خطوة خطوة**، وفي كل خطوة تختار الخيار الذي يبدو **الأفضل الآن** حسب قاعدة بسيطة، ولا تراجع أي قرار أبداً. مثل متسلق جبل في الضباب: يصعد دائماً في الاتجاه الأكثر ارتفاعاً أمامه.

**لماذا نستخدمها؟** لأنها **بسيطة** و**سريعة جداً** (غالباً ترتيب واحد ثم مرور واحد). وعندما تكون صحيحة، لا يوجد ما هو أفضل منها.

**أين تُستخدم؟** رأيتها مرتين من قبل: [Dijkstra](../shortest-path/) تأخذ أقرب مدينة، و [Kruskal و Prim](../mst/) تأخذ أرخص كابل. وتُستخدم أيضاً في ضغط الملفات (هوفمان)، وجدولة المهام، وإعطاء الفكّة في آلات البيع.

</Concept>

لكن انتبه: الخطر الكبير في الطمع أنه **يبدو صحيحاً دائماً**. المتسلق في الضباب قد يصل إلى قمة تلة صغيرة، ويظن أنه على قمة الجبل. لذلك **كل خوارزمية جشعة تحتاج إثباتاً**، أو مثالاً مضاداً يكسرها.

## آلة الفكّة

المسألة: أعطِ الزبون المبلغ بأقل عدد من القطع. والطريقة الجشعة الطبيعية: **أكبر قطعة ممكنة، ثم كرّر**.

<CoinMachine />

**ماذا يجب أن ترى؟**

1. مع القطع 1، 5، 10، 25 والمبلغ 63: الجشع يعطي 25، 25، 10، 1، 1، 1 (6 قطع)، وهذا أفضل حل. اضغط «ابحث عن أول مبلغ يفشل»: **لا يوجد** حتى 99.
2. غيّر إلى 1، 3، 4، ثم «ابحث»: المبلغ **6**. الجشع يأخذ 4 ثم 1 ثم 1 (3 قطع)، والأفضل 3 + 3 (قطعتان فقط)!
3. ومع 1، 7، 10: المبلغ **14**. الجشع 10 + 1 + 1 + 1 + 1 (5 قطع)، والأفضل 7 + 7.
4. جرّب نظاماً من عندك، مثل 1، 6، 9.

لماذا فشل؟ لأن أخذ 4 **أفسد** الباقي: بقي 2، ولا يُدفع إلا بقطعتين صغيرتين. الطمع لا يرى هذا المستقبل. والحل الصحيح لأي نظام قطع هو **البرمجة الديناميكية** (الصفحة التالية).

<TabItem label="Python">

```python
def greedy_change(amount, coins):
    out = []
    for c in sorted(coins, reverse=True):   # biggest coin first
        while amount >= c:
            out.append(c)
            amount -= c
    return out

print(greedy_change(63, [1, 5, 10, 25]))   # [25, 25, 10, 1, 1, 1]  optimal
print(greedy_change(6, [1, 3, 4]))         # [4, 1, 1]  but [3, 3] is better!
```

</TabItem>
<TabItem label="C++">

```cpp
vector<int> greedyChange(int amount, vector<int> coins) {
    sort(coins.rbegin(), coins.rend());     // biggest first
    vector<int> out;
    for (int c : coins)
        while (amount >= c) { out.push_back(c); amount -= c; }
    return out;
}
// greedyChange(6, {1, 3, 4}) -> {4, 1, 1}, not optimal
```

## جدولة القاعة

مسألة مشهورة اسمها <Term t="اختيار الأنشطة" en="Activity Selection" def="مسألة اختيار أكبر عدد من الأنشطة التي لا تتداخل أوقاتها، لتنفيذها في مكان واحد أو بمورد واحد." />: قاعة واحدة، وأنشطة لكل منها وقت بداية ونهاية. نريد **أكبر عدد** من الأنشطة دون تداخل. هناك ثلاث قواعد جشعة تبدو منطقية، فأيها الصحيحة؟

<HallSchedule />

**ماذا يجب أن ترى؟**

1. حاول بنفسك أولاً: هل تصل إلى 4 أنشطة؟
2. **يبدأ أولاً:** يأخذ الورشة الطويلة (7:30 إلى 15:00) فتحتل القاعة: **نشاط واحد فقط**!
3. **الأقصر أولاً:** يأخذ الندوة القصيرة، فيخسر نشاطين يتداخلان معها: **3 أنشطة**.
4. **ينتهي أولاً:** **4 أنشطة**، وهذا الأفضل دائماً.

<Tabs syncKey="algo-lang">
<TabItem label="Python">

```python
def select_activities(acts):            # acts: list of (start, end, name)
    chosen, free_at = [], float("-inf")
    for s, e, name in sorted(acts, key=lambda a: a[1]):   # earliest end first
        if s >= free_at:                 # the hall is free
            chosen.append(name)
            free_at = e
    return chosen
```

</TabItem>
<TabItem label="C++">

```cpp
vector<string> selectActivities(vector<tuple<double,double,string>> acts) {
    sort(acts.begin(), acts.end(), [](auto& x, auto& y) {
        return get<1>(x) < get<1>(y);    // earliest end first
    });
    vector<string> chosen;
    double freeAt = -1e18;
    for (auto& [s, e, name] : acts)
        if (s >= freeAt) { chosen.push_back(name); freeAt = e; }
    return chosen;
}
```

</TabItem>
</Tabs>

الزمن $O(n \log n)$ للترتيب، ثم مرور واحد $O(n)$.

### لماذا «ينتهي أولاً» صحيحة؟

نستخدم <Term t="حجة التبديل" en="Exchange Argument" def="طريقة لإثبات صحة خوارزمية جشعة: نأخذ أي حل أمثل، ونبيّن أننا نستطيع أن نستبدل أحد اختياراته باختيار الجشع دون أن يسوء الحل." />:

1. خذ **أي** جدول أمثل (فيه أكبر عدد ممكن من الأنشطة).
2. انظر إلى أول نشاط فيه. النشاط الذي **ينتهي أولاً** بين كل الأنشطة ينتهي في الوقت نفسه أو قبله.
3. **بدّل** أول نشاط في الجدول الأمثل بالنشاط الذي ينتهي أولاً. لا يتداخل مع الباقي، لأنه ينتهي أبكر. والعدد لم يتغيّر، فالجدول ما زال أمثل!
4. كرّر الحجة نفسها مع الباقي. إذن الجشع يصنع جدولاً أمثل.

## حقيبة الظهر: كسرية أم كاملة؟

حقيبة سعتها 10 كيلو، وأغراض لكل منها وزن وقيمة. نريد أكبر قيمة. والقاعدة الجشعة الطبيعية: **الأعلى قيمة لكل كيلو أولاً**.

- **الحقيبة الكسرية:** يمكن أن نأخذ **جزءاً** من الغرض (مثل نصف كيس سكر). هنا الطمع **صحيح دائماً**: نملأ بالأغلى لكل كيلو، والجزء الأخير نقطعه.
- **حقيبة 0/1:** إما أن تأخذ الغرض كله أو تتركه (مثل خيمة). هنا الطمع **يفشل**: سترى في الصفحة التالية مثالاً يعطي فيه الطمع 44، والأفضل 46.

## ترميز هوفمان

كيف يضغط الحاسوب نصاً؟ الحروف الكثيرة (مثل الألف واللام في العربية) نعطيها **رموزاً قصيرة**، والنادرة رموزاً طويلة، كما في شيفرة مورس. و<Term t="ترميز هوفمان" en="Huffman Coding" def="طريقة ضغط جشعة: تدمج في كل خطوة أقل حرفين تكراراً في عقدة واحدة، فتبني شجرة تعطي الحروف الكثيرة رموزاً قصيرة والنادرة رموزاً طويلة." /> يبني أفضل رموز ممكنة بطريقة جشعة:

1. ضع كل حرف مع عدد مرات ظهوره في **طابور أولوية** (الأقل أولاً).
2. أخرج **أقل اثنين**، وادمجهما في عقدة واحدة مجموعها مجموعهما، وأعدها إلى الطابور.
3. كرّر حتى تبقى عقدة واحدة: هي جذر الشجرة. واليسار 0 واليمين 1.

مثلاً في كلمة `ABRACADABRA`: ‏A تظهر 5 مرات، فيصبح رمزها بتاً واحداً، بدل 8 بتات في الترميز العادي. وهذه الفكرة داخل صيغ <Term t="ZIP" en="ZIP Archive Format" def="صيغة مشهورة لضغط الملفات وجمعها في ملف واحد." /> و <Term t="JPEG" en="Joint Photographic Experts Group" def="صيغة مشهورة لضغط الصور." /> و <Term t="MP3" en="MPEG Audio Layer III" def="صيغة مشهورة لضغط الصوت." />.

## الخلاصة

- **الجشع**: في كل خطوة خذ الأفضل الآن، ولا ترجع. بسيط وسريع.
- **يخدعك أحياناً**: الفكّة بالقطع 1، 3، 4 للمبلغ 6، وحقيبة 0/1.
- **جدولة الأنشطة**: «ينتهي أولاً» صحيحة دائماً، و«يبدأ أولاً» و«الأقصر» تفشلان.
- نثبت صحة الجشع **بحجة التبديل**، ونحتاج **خاصية الاختيار الجشع** و**البنية الجزئية المثلى**.
- أمثلة ناجحة: Dijkstra، و Kruskal، و Prim، والحقيبة الكسرية، و**هوفمان**.
