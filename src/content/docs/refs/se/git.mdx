## ماذا ستتعلم؟

- لماذا يحتاج كل مشروع برمجي إلى **إدارة الإصدارات**.
- المناطق الثلاث: **مجلد العمل**، و**منطقة التجهيز**، و**المستودع**.
- كيف تأخذ **لقطة**، وتنشئ **فرعاً**، و**تدمج**.
- الفرق بين Git و GitHub، وكيف يعمل الفريق معاً.

## لماذا Git؟

<Concept term="نظام إدارة الإصدارات" en="Version Control System">

برنامج يحفظ **تاريخ** كل ملفات المشروع: كل تغيير، ومن قام به، ومتى، ولماذا. مثل زر «تراجع» لا حدود له، يعمل على المشروع كله، ولكل الفريق.

**لماذا نستخدمه؟** لنعود إلى أي نسخة سابقة إذا خرّبنا شيئاً، ولنعرف من غيّر هذا السطر ولماذا، وليعمل عدة مبرمجين على المشروع نفسه في الوقت نفسه دون أن يمسح أحدهم عمل الآخر.

**أين يُستخدم؟** في كل شركة برمجيات تقريباً. وأشهر نظام اليوم هو <Term t="Git" en="Git" def="أشهر نظام لإدارة الإصدارات، كتبه لينوس تورفالدز عام 2005 لإدارة كود نواة لينكس، ويعمل على جهاز كل مبرمج." />. وهذا الموقع نفسه محفوظ في Git!

</Concept>

## المناطق الثلاث

أهم فكرة في Git: الملف يمر بثلاث مناطق قبل أن يُحفظ في التاريخ. مثل التصوير الجماعي: الناس يتحركون في الغرفة (**مجلد العمل**)، ثم تختار من يقف أمام الكاميرا (**منطقة التجهيز**)، ثم تضغط زر التصوير (**اللقطة**).

| المنطقة | ماذا فيها | الأمر الذي ينقل إليها |
| --- | --- | --- |
| **مجلد العمل** | الملفات كما تعدّلها الآن | (أنت تعدّل الملفات) |
| **منطقة التجهيز** | التغييرات التي اخترتها للقطة التالية | `git add` |
| **المستودع** | كل اللقطات المحفوظة، بالترتيب | `git commit` |

كل لقطة اسمها <Term t="commit" en="Commit" def="لقطة محفوظة لكل ملفات المشروع في لحظة معيّنة، لها رقم ورسالة تصف التغيير، وتشير إلى اللقطة التي قبلها." />، ولها رقم مميز ورسالة تشرح **ماذا** تغيّر **ولماذا**.

## جرّب بنفسك

الطرفية التالية تفهم أهم أوامر Git، وترسم لك اللقطات والفروع مع كل أمر. نفّذ المهمات بالترتيب:

<GitLab />

**ماذا يجب أن ترى؟**

1. بعد `git init`: «لا توجد لقطات بعد».
2. بعد أول `git commit`: دائرة خضراء واحدة، وفوقها `HEAD → main`. و <Term t="HEAD" en="HEAD" def="مؤشر في Git يبيّن أين أنت الآن: على أي فرع، وعند أي لقطة." /> يعني «أنت هنا».
3. بعد إنشاء `feature` وأخذ لقطة عليه: خط ثانٍ تحت الخط الرئيسي.
4. بعد العودة إلى `main`، يختفي `login.txt` من `ls`! لم يُحذف، بل هو محفوظ في فرع `feature` فقط.
5. بعد لقطة جديدة على `main`: صار الخطان منفصلين، ولكل منهما لقطة لا يعرفها الآخر.
6. بعد الدمج: دائرة برتقالية لها أبوان، وصار `login.txt` موجوداً في `main`.

## الفروع: اعمل دون أن تخرّب

<Concept term="الفرع" en="Branch">

**خط عمل منفصل** يبدأ من لقطة معيّنة، فتجرّب فيه ميزة جديدة دون أن تلمس النسخة الأساسية. مثل مسودة تكتبها على ورقة منفصلة، ثم تنقلها إلى الدفتر عندما تكون جاهزة.

**لماذا نستخدمه؟** لأن النسخة الأساسية (`main`) يجب أن تعمل دائماً. وكل مبرمج يعمل على ميزته في فرعه، ثم ندمج بعد أن نراجعها ونختبرها.

**أين يُستخدم؟** في كل فريق: فرع لكل ميزة، وفرع لكل إصلاح خطأ عاجل.

</Concept>

<Aside type="caution" title="التعارض">
إذا عدّل فرعان **السطر نفسه** من الملف نفسه بطريقتين مختلفتين، لا يعرف Git أيهما الصحيح، فيوقف الدمج ويطلب منك أن تختار. وهذا اسمه <Term t="التعارض" en="Merge Conflict" def="حالة يعدّل فيها فرعان السطر نفسه بطريقتين مختلفتين، فلا يستطيع Git أن يدمجهما وحده، ويطلب من المبرمج أن يقرر." />. المحاكي هنا لا يُظهر التعارضات للتبسيط، لكنها تحدث كثيراً في الواقع، ونحلها بالتنسيق بين أعضاء الفريق.
</Aside>

## Git و GitHub

| | **Git** | **GitHub** |
| --- | --- | --- |
| ما هو؟ | برنامج على جهازك | موقع على الإنترنت |
| وظيفته | يحفظ تاريخ المشروع | يحفظ نسخة من المستودع ليشاركه الفريق |
| يعمل دون إنترنت؟ | نعم | لا |

نرسل لقطاتنا إلى المستودع على الإنترنت بالأمر `git push`، ونجلب لقطات زملائنا بالأمر `git pull`. وفي GitHub نطلب دمج فرعنا بـ<Term t="طلب الدمج" en="Pull Request" def="طلب في GitHub لدمج فرع في الفرع الرئيسي، يراجع فيه الزملاء الكود ويعلّقون عليه قبل الموافقة." />، فيراجع الزملاء الكود قبل الموافقة (تذكّر [مراجعة الكود](../quality-metrics/)).

## الخلاصة

- **Git** يحفظ تاريخ المشروع كله، ويسمح للفريق بالعمل معاً.
- المناطق الثلاث: **مجلد العمل** ← `git add` ← **التجهيز** ← `git commit` ← **المستودع**.
- **الفرع** خط عمل منفصل، و**الدمج** يجمع الفرعين. والتعارض يحدث عندما يعدّل فرعان السطر نفسه.
- **GitHub** موقع يحفظ نسخة مشتركة، ونرسل إليه بـ `git push` ونجلب منه بـ `git pull`.

## أسئلة المراجعة

<details class="answer">
<summary>ما فائدة منطقة التجهيز؟ لماذا لا نحفظ كل التغييرات مباشرة؟</summary>

لنختار ما يدخل في كل لقطة، فتكون كل لقطة عن تغيير واحد واضح. مثلاً: إصلاح خطأ في لقطة، وميزة جديدة في لقطة أخرى، حتى لو عدّلناهما في الوقت نفسه.
</details>

<details class="answer">
<summary>لماذا اختفى login.txt عندما عدت إلى main؟</summary>

لأنه أُضيف في لقطة على فرع `feature` فقط. وعند الانتقال إلى `main` يعرض Git الملفات كما هي في آخر لقطة على `main`. والملف لم يُحذف، وعاد بعد الدمج.
</details>

<details class="answer">
<summary>ما هي لقطة الدمج، ولماذا لها أبوان؟</summary>

لقطة تجمع عمل فرعين، فأبوها الأول آخر لقطة على الفرع الحالي، والثاني آخر لقطة على الفرع المدموج.
</details>

<details class="answer">
<summary>ما الفرق بين Git و GitHub؟</summary>

Git برنامج على جهازك يحفظ تاريخ المشروع ويعمل دون إنترنت. و GitHub موقع على الإنترنت يحفظ نسخة من المستودع ليشاركها الفريق، ويضيف المراجعة وطلبات الدمج.
</details>
