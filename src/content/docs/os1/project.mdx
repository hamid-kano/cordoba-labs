## المطلوب

كل مجموعة تنفّذ خوارزميتين:

1. **الأساس**: <Term t="FCFS" en="First Come, First Served" def="من يصل أولاً يُخدم أولاً، ويبقى حتى ينتهي." />، وتنفّذها كل المجموعات.
2. **خوارزمية تختارها المجموعة** عند التسجيل، من الخمس الباقية في الجلسة 4:

| الخوارزمية | من يأخذ المعالج؟ | مقاطعة؟ |
| --- | --- | --- |
| <Term t="SJF" en="Shortest Job First" def="الأقصر تنفيذاً أولاً، من بين العمليات التي وصلت." /> | الأقصر تنفيذاً | لا |
| <Term t="SRTF" en="Shortest Remaining Time First" def="مثل SJF لكن مع مقاطعة: إذا وصلت عملية أقصر مما بقي للحالية، تأخذ المعالج." /> | الأقل في ما بقي | نعم |
| <Term t="Round Robin" en="Round Robin" def="بالدور: كل عملية تأخذ شريحة زمنية صغيرة q، ثم تعود إلى آخر الطابور." /> | التالي في الطابور، لشريحة q | نعم |
| الأولوية | الأهم (الرقم الأصغر) | لا |
| الأولوية مع المقاطعة | الأهم، فوراً | نعم |

ولكل خوارزمية عدد محدود من المجموعات، فمن يسجّل أولاً يختار أولاً.

يجب أن يقوم البرنامج بما يلي:

- يقرأ العمليات من الملف `input.txt` (الصيغة في الأسفل).
- يجدول العمليات بـ FCFS، ثم بخوارزمية المجموعة.
- يرسم **مخطط Gantt** لكل خوارزمية: نصياً في الطرفية أو رسومياً، كما تريدون.
- يطبع جدولاً لكل عملية فيه: زمن الانتهاء، وزمن الدوران، وزمن الانتظار، وزمن الاستجابة.
- يطبع **المتوسطات** لكل خوارزمية، ثم **مقارنة** بينهما: أيهما أفضل في الانتظار، وفي الدوران، وفي الاستجابة.

<Aside type="caution" title="بيانات كل مجموعة مختلفة">
عند التسجيل تحصل كل مجموعة على **رمز**، ومن الرمز تخرج **بيانات عمليات خاصة بها**. سنشغّل برنامجكم في المناقشة على بياناتكم، ونقارن نتائجه بالنتائج الصحيحة.
</Aside>

## صيغة الإدخال

السطر الذي يبدأ بـ `#` تعليق. كل سطر بعده عملية: الاسم، وزمن الوصول، وزمن التنفيذ، والأولوية. ومجموعات Round Robin فقط عندها سطر أخير فيه الشريحة `q`.

```text
# name arrival burst priority
P1 0 5 3
P2 1 3 1
P3 3 8 2
q 3
```

## قواعد حسم التعادل

حتى تكون النتيجة واحدة عند الجميع (ومطابقة لمحاكي الجلسة 4):

- **الأولوية**: الرقم الأصغر هو الأهم.
- **عند التعادل** (طول التنفيذ نفسه، أو الأولوية نفسها): تُقدَّم العملية الأسبق وصولاً، ثم صاحبة الرقم الأصغر (P2 قبل P5).
- **الخوارزميات مع المقاطعة** (SRTF، والأولوية مع المقاطعة): يعاد القرار عند وصول أي عملية جديدة.
- **Round Robin**: إذا وصلت عملية في اللحظة نفسها التي انتهت فيها شريحة عملية أخرى، تدخل العملية الجديدة الطابور **قبل** العملية التي انتهت شريحتها.
- إذا لم توجد عملية جاهزة، يبقى المعالج **فارغاً** حتى تصل العملية التالية، ويظهر ذلك في مخطط Gantt.

## مثال على الإخراج

الشكل حر، لكن يجب أن تظهر هذه المعلومات كلها:

```text
=== FCFS ===
Gantt: | P1 0-5 | P2 5-8 | P3 8-16 |
Proc  Finish  Turnaround  Waiting  Response
P1    5       5           0        0
...
Average: waiting = 3.00  turnaround = 8.33  response = 3.00

=== RR (q = 3) ===
Gantt: | P1 0-3 | P2 3-6 | P3 6-9 | P1 9-11 | P3 11-16 |
...

=== Comparison ===
Waiting:    FCFS is better (3.00 vs 4.33)
...
```

## التسجيل في GitHub ورفع المشروع

إذا لم تستخدموا <Term t="GitHub" en="GitHub" def="موقع لحفظ مشاريع البرمجة ومشاركتها، ويحفظ كل نسخة من الكود مع اسم من كتبها ووقتها." /> من قبل، فهذه الخطوات تكفي:

<Steps>

1. أنشئوا حساباً على [github.com](https://github.com) (لكل عضو حسابه).

2. يُنشئ أحدكم **مستودعاً** جديداً (**New repository**)، وليكن اسمه مثلاً `os1-scheduler`، ويختار **Public**.

3. من **Settings ← Collaborators** يضيف بقية أعضاء المجموعة، حتى يستطيع كل واحد أن يرفع عمله.

4. ثبّتوا [Git](https://git-scm.com) على أجهزتكم، ثم انسخوا المستودع:

   ```bash
   git clone https://github.com/USERNAME/os1-scheduler.git
   cd os1-scheduler
   ```

5. بعد كل جزء تنجزونه، احفظوه وارفعوه:

   ```bash
   git add .
   git commit -m "FCFS: Gantt chart and averages"
   git push
   ```

   الـ <Term t="commit" en="Commit" def="لقطة محفوظة من الكود مع رسالة قصيرة تشرح ما تغيّر، ويُسجَّل معها اسم كاتبها ووقتها." /> الواحد يجب أن يكون صغيراً وواضحاً. ارفعوا عملكم **على مراحل**، لا دفعة واحدة في آخر يوم.

6. أضيفوا ملف `README.md` فيه: أسماء أعضاء المجموعة، ورمز المجموعة، وطريقة تشغيل البرنامج.

7. سلّموا رابط المستودع في نموذج التسليم في الأسفل.

</Steps>
