## ملخص نظري

### الشبكة بكلمتين

الأجهزة بتحكي مع بعض بقواعد متفق عليها اسمها **بروتوكولات**، وأشهرها **<Term t="TCP/IP" en="Transmission Control Protocol / Internet Protocol" def="مجموعة قواعد الإنترنت: IP بيوصّل الرسالة للجهاز، و TCP بيتأكد إنها وصلت كاملة." />**: الـ <Term t="IP" en="Internet Protocol" def="بروتوكول الإنترنت: بيعطي كل جهاز عنوان، وبيوصّل الرسالة للجهاز الصح." /> بيوصّل الرسالة للجهاز الصح، و <Term t="TCP" en="Transmission Control Protocol" def="بروتوكول بيتأكد إنه الرسالة وصلت كاملة وبالترتيب، وإذا ضاع شي بيعيد بعته." /> بيتأكد إنها وصلت كاملة وبالترتيب. (التفاصيل بمادة الشبكات اللاسلكية.)

### الزبون والخادم

<ClientServerDiagram />

<Concept term="النظام الموزع" en="Distributed System">

مجموعة أجهزة مستقلة موصولة بشبكة، بس بتبيّن للمستخدم كأنها **جهاز واحد**. متل Google: آلاف الخوادم، وإنت بتشوف مربع بحث واحد.

**ليش؟** قوة أكبر (كذا جهاز بيشتغلوا سوا)، وإذا وقع جهاز بيكمّل الباقي، وبتقدر تكبّره بإنك تضيف أجهزة.

**أمثلة بتستخدمها كل يوم:** واتساب، و Google Drive، ويوتيوب، والصرّاف الآلي.

</Concept>

<Concept term="الشفافية" en="Transparency">

أهم هدف بالنظام الموزع: المستخدم **ما بيحس** إنه في كذا جهاز. ما بيعرف وين البيانات محطوطة (**شفافية المكان**)، ولا إذا جهاز وقع وانبدل (**شفافية الأعطال**).

</Concept>

- <Term t="RPC" en="Remote Procedure Call" def="البرنامج بيستدعي تابع موجود على جهاز تاني، كأنه تابع عادي عنده. والنظام بيتكفّل بإرسال الطلب وجلب النتيجة عبر الشبكة." />: برنامج بيستدعي تابع موجود **على جهاز تاني** كأنه عنده. متل ما بتطلب أكل بالتلفون: بتطلب، وبيوصلك، وما بتشوف المطبخ.
- **نظام ملفات موزع** (متل Google Drive أو <Term t="NFS" en="Network File System" def="نظام ملفات موزع: الملفات على خادم، وبتشوفها كأنها عندك." />): الملفات على خادم، بس بتشوفها كأنها على جهازك.

### خدمات الويب

<Concept term="خدمة الويب" en="Web Service">

خادم بيقدّم بياناته أو خدماته **لأي برنامج** عبر الإنترنت، بلغة متفق عليها. مثلاً تطبيق الطقس بموبايلك بيطلب الحرارة من خدمة ويب، وبيعرضها بشكل حلو.

</Concept>

| الكلمة | يعني |
| --- | --- |
| **<Term t="HTTP" en="HyperText Transfer Protocol" def="لغة الطلب والرد بين المتصفح والخادم بالويب." />** | لغة الطلب والرد بالويب: `GET` لتجيب، و `POST` لتبعت |
| **<Term t="HTTPS" en="HyperText Transfer Protocol Secure" def="نفس HTTP بس مشفّر: القفل 🔒 بالمتصفح." />** | نفس HTTP بس **مشفّر** (القفل 🔒 بالمتصفح) |
| **<Term t="REST" en="Representational State Transfer" def="طريقة بسيطة لتصميم خدمات الويب: كل شي إله عنوان." />** | طريقة بسيطة لتصميم خدمات الويب: كل شي إله عنوان (متل `/students/5`) |
| **JSON** | صيغة لكتابة البيانات بيفهمها أي برنامج: `{"name": "أحمد", "mark": 85}` |
| **<Term t="XML" en="eXtensible Markup Language" def="صيغة لكتابة البيانات بوسوم متل HTML، أطول من JSON." />** و **<Term t="SOAP" en="Simple Object Access Protocol" def="طريقة أقدم لخدمات الويب، بتستخدم XML." />** | صيغة وطريقة أقدم وأطول من JSON و REST |
| **رمز الرد** | `200` يعني تمام، و `404` يعني مش موجود، و `500` يعني الخادم فيه مشكلة |

## خطوات العملي

### 1. فكّك الرابط

<NetLab tool="url" />

<Steps>

1. خلي الرابط الجاهز. **شو لازم تشوف:** البروتوكول `https`، والخادم `api.example.com`، والمسار `/students/5`، ومعاملين: `year=3` و `city=Aleppo`.

2. غيّر `https` لـ `http`. **شو لازم تشوف:** ⚠️ تحذير إنه الاتصال مش مشفّر.

3. انسخ رابط من يوتيوب أو Google وحطه هون. **شو لازم تشوف:** المعاملات يلي بعد `?` (متل `v=` بيوتيوب هو رقم الفيديو).

</Steps>

### 2. طلب حقيقي من خادم

<NetLab tool="request" />

<Steps>

1. اكبس **«اطلب students.json»**. **شو لازم تشوف:** الطلب `GET`، ورد الخادم **200 OK**، والوقت بالـ ms، والبيانات بصيغة **JSON**، وتحتها نفس البيانات بجدول بعد ما «فهمها» التطبيق.

2. اكبس **«اطلب ملف مش موجود»**. **شو لازم تشوف:** **404 Not Found**.

3. (على لابتوب) اكبس **F12** ← تبويب **Network**، وأعد الخطوة 1. **شو لازم تشوف:** الطلب نفسه بالقائمة، وإذا كبست عليه بتشوف **Headers** و **Response**.

4. وإنت فاتح Network، حدّث أي موقع (متل Google). **شو لازم تشوف:** عشرات الطلبات! كل صورة وكل ملف هو طلب لخادم.

</Steps>

### 3. مسألة محلولة: اقرأ الـ JSON

**السؤال:** خدمة ويب رجّعت هالرد. شو اسم الطالب التاني؟ وكم طالب من حلب؟

```json
{
  "course": "نظم التشغيل 1",
  "students": [
    { "id": 1, "name": "أحمد", "city": "حلب", "mark": 85 },
    { "id": 2, "name": "سارة", "city": "دمشق", "mark": 92 },
    { "id": 4, "name": "ليلى", "city": "حلب", "mark": 73 }
  ]
}
```

**الحل:**

- `{ }` يعني **كائن** فيه أسماء وقيم، و `[ ]` يعني **قائمة**.
- `students` قائمة فيها 3 كائنات. التاني هو `"name": "سارة"`.
- العناصر يلي `"city": "حلب"`: أحمد وليلى، يعني **2**.

## النتيجة المتوقعة

- بتشرح الزبون والخادم و RPC بمثال من الحياة.
- بتفكّك أي رابط وبتعرف إذا الاتصال مشفّر.
- بتقرأ رد JSON وبتفهم رموز الرد 200 و 404.

## أخطاء شائعة

| الخطأ | الصح |
| --- | --- |
| النظام الموزع = شبكة | الشبكة بتوصّل الأجهزة. النظام الموزع بيخليها **تبيّن كجهاز واحد** |
| `404` يعني الإنترنت مقطوع | `404` يعني الخادم وصل بس الشي المطلوب مش موجود |
| HTTP و HTTPS نفس الشي | HTTPS **مشفّر**، و HTTP لأ |
| الجزء بعد `#` بينبعت للخادم | لأ، هو للمتصفح بس (مكان جوّا الصفحة) |

## الوظيفة

1. اكتب 3 أمثلة على أنظمة موزعة بتستخدمها كل يوم، وشو الزبون والخادم بكل واحد.
2. فكّك هالرابط بإيدك، وتأكد بالأداة: `https://shop.example.com/products/42?color=red&size=M`
3. اكتب JSON لطالب: اسمه، ومدينته، وقائمة علاماته بـ 3 مواد.

## أسئلة المراجعة

<details class="answer">
<summary>شو هو RPC؟</summary>

استدعاء تابع موجود على جهاز تاني كأنه محلي. النظام بيبعت الطلب عبر الشبكة وبيرجّع النتيجة.
</details>

<details class="answer">
<summary>شو يعني الشفافية بالنظام الموزع؟</summary>

إنه المستخدم ما بيحس إنه في كذا جهاز: ما بيعرف وين البيانات، ولا إذا جهاز وقع وانبدل.
</details>

<details class="answer">
<summary>شو بيعني الرد <code>200</code> و <code>404</code>؟</summary>

`200` الطلب نجح. `404` الشي المطلوب مش موجود على الخادم.
</details>

<details class="answer">
<summary>شو الفرق بين <code>{ }</code> و <code>[ ]</code> بالـ JSON؟</summary>

`{ }` كائن فيه أسماء وقيم. `[ ]` قائمة عناصر بالترتيب.
</details>

<details class="answer">
<summary>شو بيعني <code>?year=3</code> بآخر الرابط؟</summary>

معامل بينبعت مع الطلب: اسمه `year` وقيمته `3`، متل فلتر للنتائج.
</details>
