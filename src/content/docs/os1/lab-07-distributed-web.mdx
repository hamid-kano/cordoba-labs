## ملخص نظري

### الشبكة باختصار

تتواصل الأجهزة مع بعضها بقواعد متفق عليها اسمها **بروتوكولات**، وأشهرها **<Term t="TCP/IP" en="Transmission Control Protocol / Internet Protocol" def="مجموعة قواعد الإنترنت: يوصل IP الرسالة إلى الجهاز، ويتأكد TCP من وصولها كاملة." />**: يوصل الـ <Term t="IP" en="Internet Protocol" def="بروتوكول الإنترنت: يعطي كل جهاز عنواناً، ويوصل الرسالة إلى الجهاز الصحيح." /> الرسالة إلى الجهاز الصحيح، ويتأكد <Term t="TCP" en="Transmission Control Protocol" def="بروتوكول يتأكد من وصول الرسالة كاملة وبالترتيب، وإذا ضاع جزء منها يعيد إرساله." /> من أنها وصلت كاملة وبالترتيب. (التفاصيل في مادة الشبكات اللاسلكية.)

### الزبون والخادم

<ClientServerDiagram />

<Concept term="النظام الموزع" en="Distributed System">

مجموعة أجهزة مستقلة متصلة بشبكة، لكنها تبدو للمستخدم كأنها **جهاز واحد**. مثل Google: آلاف الخوادم، وأنت ترى مربع بحث واحداً.

**لماذا؟** قوة أكبر (عدة أجهزة تعمل معاً)، وإذا تعطّل جهاز يكمل الباقون، ويمكن توسيعه بإضافة أجهزة.

**أمثلة تستخدمها كل يوم:** واتساب، و Google Drive، ويوتيوب، والصرّاف الآلي.

</Concept>

<Concept term="الشفافية" en="Transparency">

أهم هدف في النظام الموزع: **لا يشعر** المستخدم بوجود عدة أجهزة. لا يعرف أين توضع البيانات (**شفافية المكان**)، ولا إذا تعطّل جهاز واستُبدل (**شفافية الأعطال**).

</Concept>

- <Term t="RPC" en="Remote Procedure Call" def="يستدعي البرنامج تابعاً موجوداً على جهاز آخر، كأنه تابع عادي لديه. ويتكفّل النظام بإرسال الطلب وجلب النتيجة عبر الشبكة." />: يستدعي برنامج تابعاً موجوداً **على جهاز آخر** كأنه لديه. مثلما تطلب طعاماً بالهاتف: تطلب، فيصلك، ولا ترى المطبخ.
- **نظام ملفات موزع** (مثل Google Drive أو <Term t="NFS" en="Network File System" def="نظام ملفات موزّع: الملفات على خادم، وتراها كأنها على جهازك." />): الملفات على خادم، لكنك تراها كأنها على جهازك.

### خدمات الويب

<Concept term="خدمة الويب" en="Web Service">

خادم يقدّم بياناته أو خدماته **لأي برنامج** عبر الإنترنت، بلغة متفق عليها. مثلاً يطلب تطبيق الطقس في هاتفك درجة الحرارة من خدمة ويب، ثم يعرضها بشكل جميل.

</Concept>

| الكلمة | معناها |
| --- | --- |
| **<Term t="HTTP" en="HyperText Transfer Protocol" def="لغة الطلب والرد بين المتصفح والخادم في الويب." />** | لغة الطلب والرد في الويب: `GET` لتجلب، و `POST` لترسل |
| **<Term t="HTTPS" en="HyperText Transfer Protocol Secure" def="هو HTTP لكنه مشفّر: القفل 🔒 في المتصفح." />** | HTTP نفسه لكنه **مشفّر** (القفل 🔒 في المتصفح) |
| **<Term t="REST" en="Representational State Transfer" def="طريقة بسيطة لتصميم خدمات الويب: لكل شيء عنوان." />** | طريقة بسيطة لتصميم خدمات الويب: لكل شيء عنوان (مثل `/students/5`) |
| **JSON** | صيغة لكتابة البيانات يفهمها أي برنامج: `{"name": "أحمد", "mark": 85}` |
| **<Term t="XML" en="eXtensible Markup Language" def="صيغة لكتابة البيانات بوسوم مثل HTML، وهي أطول من JSON." />** و **<Term t="SOAP" en="Simple Object Access Protocol" def="طريقة أقدم لخدمات الويب، تستخدم XML." />** | صيغة وطريقة أقدم وأطول من JSON و REST |
| **رمز الرد** | `200` يعني نجح، و `404` يعني غير موجود، و `500` يعني أن في الخادم مشكلة |

## خطوات العملي

### 1. فكّك الرابط

<NetLab tool="url" />

<Steps>

1. اترك الرابط الجاهز. **ماذا يجب أن ترى؟** البروتوكول `https`، والخادم `api.example.com`، والمسار `/students/5`، ومعاملين: `year=3` و `city=Aleppo`.

2. غيّر `https` إلى `http`. **ماذا يجب أن ترى؟** ⚠️ تحذيراً بأن الاتصال غير مشفّر.

3. انسخ رابطاً من يوتيوب أو Google وضعه هنا. **ماذا يجب أن ترى؟** المعاملات التي بعد `?` (مثل `v=` في يوتيوب، وهو رقم الفيديو).

</Steps>

### 2. طلب حقيقي من خادم

<NetLab tool="request" />

<Steps>

1. اضغط **«اطلب students.json»**. **ماذا يجب أن ترى؟** الطلب `GET`، ورد الخادم **200 OK**، والوقت بالـ ms، والبيانات بصيغة **JSON**، وتحتها البيانات نفسها في جدول بعد أن «فهمها» التطبيق.

2. اضغط **«اطلب ملفاً غير موجود»**. **ماذا يجب أن ترى؟** **404 Not Found**.

3. (على حاسوب) اضغط **F12** ← تبويب **Network**، وأعد الخطوة 1. **ماذا يجب أن ترى؟** الطلب نفسه في القائمة، وإذا ضغطت عليه ترى **Headers** و **Response**.

4. وتبويب Network مفتوح، حدّث أي موقع (مثل Google). **ماذا يجب أن ترى؟** عشرات الطلبات! فكل صورة وكل ملف هو طلب إلى خادم.

</Steps>

### 3. مسألة محلولة: اقرأ الـ JSON

**السؤال:** أعادت خدمة ويب هذا الرد. ما اسم الطالب الثاني؟ وكم طالباً من حلب؟

```json
{
  "course": "نظم التشغيل 1",
  "students": [
    { "id": 1, "name": "أحمد", "city": "حلب", "mark": 85 },
    { "id": 2, "name": "سارة", "city": "دمشق", "mark": 92 },
    { "id": 4, "name": "ليلى", "city": "حلب", "mark": 73 }
  ]
}
```

**الحل:**

- `{ }` تعني **كائناً** فيه أسماء وقيم، و `[ ]` تعني **قائمة**.
- `students` قائمة فيها 3 كائنات. والثاني هو `"name": "سارة"`.
- العناصر التي فيها `"city": "حلب"`: أحمد وليلى، أي **2**.

## النتيجة المتوقعة

- تشرح الزبون والخادم و RPC بمثال من الحياة.
- تفكّك أي رابط وتعرف هل الاتصال مشفّر.
- تقرأ رد JSON وتفهم رموز الرد 200 و 404.

## أخطاء شائعة

| الخطأ | الصحيح |
| --- | --- |
| النظام الموزع = شبكة | الشبكة تصل الأجهزة، والنظام الموزع يجعلها **تبدو جهازاً واحداً** |
| `404` يعني أن الإنترنت مقطوع | `404` يعني أن الخادم وصل لكن الشيء المطلوب غير موجود |
| HTTP و HTTPS الشيء نفسه | HTTPS **مشفّر**، و HTTP غير مشفّر |
| الجزء بعد `#` يُرسل إلى الخادم | لا، هو للمتصفح فقط (مكان داخل الصفحة) |

2. فكّك هذا الرابط بيدك، وتأكد بالأداة: `https://shop.example.com/products/42?color=red&size=M`
3. اكتب JSON لطالب: اسمه، ومدينته، وقائمة علاماته في 3 مواد.

## أسئلة المراجعة

<details class="answer">
<summary>ما هو RPC؟</summary>

استدعاء تابع موجود على جهاز آخر كأنه محلي. يرسل النظام الطلب عبر الشبكة ويعيد النتيجة.
</details>

<details class="answer">
<summary>ما معنى الشفافية في النظام الموزع؟</summary>

ألا يشعر المستخدم بوجود عدة أجهزة: لا يعرف أين البيانات، ولا إذا تعطّل جهاز واستُبدل.
</details>

<details class="answer">
<summary>ما معنى الرد <code>200</code> و <code>404</code>؟</summary>

`200`: نجح الطلب. و `404`: الشيء المطلوب غير موجود على الخادم.
</details>

<details class="answer">
<summary>ما الفرق بين <code>{ }</code> و <code>[ ]</code> في الـ JSON؟</summary>

`{ }` كائن فيه أسماء وقيم. و `[ ]` قائمة عناصر بالترتيب.
</details>

<details class="answer">
<summary>ما معنى <code>?year=3</code> في نهاية الرابط؟</summary>

معامل يُرسل مع الطلب: اسمه `year` وقيمته `3`، مثل مرشّح للنتائج.
</details>
